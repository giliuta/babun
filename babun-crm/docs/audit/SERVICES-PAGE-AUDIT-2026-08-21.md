# Страница «Услуги» — аудит и план, 2026-08-21

Заход по просьбе владельца: «зайди на страницу услуги, протыкай каждую кнопочку,
посмотри по дизайну, составь план — что улучшить, добавить, упростить; чтобы было
как можно меньше тапов». **Ничего не правил — только смотрел.**

Три источника, и каждая находка помечена своим:
- **[сим]** — протапано руками в симуляторе на живом прод-тенанте, есть скриншот;
- **[SQL]** — проверено запросом по проду `rdtokosbqvgemicqeqwz`;
- **[код]** — прочитано в исходниках, путь и строка названы.

Плюс десять параллельных линз аудита (тапы, дизайн-система, корректность, деньги
вниз по течению, данные прода, отраслевые CRM, доступность, состояния, веб-паритет,
архитектура) — ~190 сырых находок, каждый заявленный дефект отдельно пытались
опровергнуть. Ниже — то, что выжило, без повторов.

---

## 0. Фактура, об которую всё меряется

**Прод сегодня [SQL].** 6 услуг у 2 тенантов из 19. Активных 5, убранная 1.
Лестница цены и времени заполнена **у одной услуги**. Описание — **у нуля**
(колонке один день, судить нельзя). Цена 0 — ни у одной. Длительность не кратная
пяти — ни у одной. У тенанта `0fc7451a` все три услуги одного цвета `#3b82f6`
— это дефолт колонки, а не выбор человека.

**Лестница ни разу не сработала [SQL].** Количество > 1 стоит в 7 строках записей,
но единственная услуга с лестницей (`A/C Cleaning`) во всех записях идёт с
количеством 1. Механизм построен, покрыт тестами и **ни разу не посчитал реальных
денег**. Значит, решения по нему (§2-2, §2-3) ещё можно принять без миграции данных.

**Три из четырёх сохранённых ступеней не меняют ничего [SQL + арифметика].**
У `A/C Cleaning`: база €50 / 30 мин, ступени `price [{2,50},{3,45}]`,
`duration [{2,60},{3,90}]`. Без лестницы движок дал бы при 2 штуках €50 и 60 мин,
при 3 — 90 мин. Совпадает всё, кроме цены на «от 3». Причина в §2-4: новая строка
приезжает с уже проставленным временем `база × количество`, человек правит только
цену — и молча сохраняет три no-op'а.

**Продолжающаяся потеря данных [SQL].** 4 из 7 id услуг, на которые ссылаются
записи, физически отсутствуют в `services` — это **17 ссылок из 20**. Причина жива:

```
services_team_fk  →  ON DELETE CASCADE     (pg_constraint, проверено сегодня)
```

Удаление бригады сносит прайс **жёстко**, мимо мягкого удаления, на котором стоит
весь продукт. Это дефект из `SERVICES-BRAINSTORM-2026-08-20.md` — сутки спустя не закрыт.

**Дрейф миграций [SQL].** На проде 8 миграций по услугам с 17 августа,
в репозитории — 3 файла. Отсутствуют:

| Прод | Что откатится при подъёме из репо |
|---|---|
| `20260817195637 services_belong_to_one_team` | `team_id NOT NULL` — фундамент сегодняшнего экрана |
| `20260818112332 service_color_returns_with_readers` | цвет услуги |
| `20260818134932 master_services_projection_returns_color` | тело RPC каталога мастера |
| `20260819095608 service_unit_of_measure` | тело RPC (единица уже снесена сверху) |

Авария класса `city_manual`, которая уже была.

**Граница применимости.** Прайса длиннее трёх строк не существует ни у одного
тенанта. Ни один вывод про длинный прайс (поиск, группировка, массовые правки)
не проверен на живых данных.

## 1. Сломано прямо сейчас

### P0-1. В ячейку таблицы влезает РОВНО ОДИН символ за тап

**[сим], четыре независимых прогона.** «Новая услуга» → тап по «Цена за одну» →
`1`,`2`,`5`,`9` отдельными нажатиями. В поле осталось **`1`**. Перетапнул поле →
`7`,`8`. В поле **`7`**. Ровно один символ на тап, дальше поле мертво.

**Механизм — одна строка [код].** `src/features/services/ServiceRows.tsx:130`:

```jsx
export function ServiceRows({ ... }) {
  ...
  const Block = ({ label, width, children }) => (   // ← объявлен ВНУТРИ рендера
    <View style={{ width }}>...</View>
  );
  ...
  <Block label="Цена за одну, €" width={MONEY_W}>{...CellInput...}</Block>
```

`Block` — новый тип компонента на каждый рендер. React не узнаёт его и
**размонтирует всё поддерево**, включая нативный `TextInput`. Первое нажатие →
`onPriceChange` → `setPrice` в листе → рендер → новый `Block` → поле уничтожено →
фокус потерян. Второй символ уходит в никуда.

**Что это значит.** Любую цену от €10 и любое количество от 10 напечатать
**нельзя** — только тапая по ячейке перед каждой цифрой. «Установка сплит-системы,
€250» — три тапа и три нажатия. Это центральный жест страницы, которую владелец
пересобрал вчера. Заодно три плиты перемонтируются на каждый щелчок барабана.

**Правка.** Вынести `Block` на уровень модуля, заливку передавать пропом. Одна
операция, нулевой риск. `grep -rn "^  const [A-Z][A-Za-z]* = ("` по всему
мобильному даёт единственное совпадение — второго такого места в продукте нет.

### P0-2. Убрать строку количества нечем

По задумке строку убирают долгим нажатием + системный алерт. На деле **[сим]**:

| Колонка | Что происходит при долгом нажатии |
|---|---|
| **Кол-во** | iOS показывает своё меню **`Select │ Select All │ AutoFill`** — по-английски, в русском приложении. `CellInput` перехватывает жест, `onLongPress` не срабатывает. Скриншот есть. |
| **Цена за одну** | Ничего. `onLongPress` там не навешан вообще — ячейка обёрнута в простой `View`. |
| **Время на всё** | Работает: «Убрать «от 4»? · от 4 — 2 ч 40 мин на всё». |

**Дублёр жеста словом работает на трети строки**, на второй трети выдаёт чужое
английское меню, на последней не существует. Видимого способа нет вообще: ни
крестика, ни свайпа, ни кнопки.

**Довесок [код].** `SwipeRow.tsx` про `accessibilityActions` только **пишет в
комментарии** (строка 175) — в коде их нет. ДС §5 требует двух дублёров: меню по
долгому нажатию и `accessibilityActions`. Нет ни одного. Следствие для списка:
**«Дубль» существует ТОЛЬКО в свайпе вправо** — ни кнопки, ни меню, ни ротора.
Для незрячего дублирования услуги в продукте нет; для зрячего оно ничем не объявлено.
Там же: ручка перетаскивания объявлена `accessibilityRole="adjustable"`, но
`increment`/`decrement` никто не обрабатывает — **порядок услуг с VoiceOver не меняется**.

**И то единственное действие, что объявлено, произносится по-английски.** У ячейки
количества есть `accessibilityActions: [{ name: "longpress", label: "Убрать количество" }]`.
Приложение собрано на **Новой архитектуре** (`app.json: newArchEnabled: true`, RN 0.81.5),
а Fabric строит `UIAccessibilityCustomAction` **только из `name`** —
`RCTViewComponentView.mm:1343-1359`, поле `label` не читается вовсе (его читает лишь
старая архитектура, `RCTView.m:249-269`). В роторе звучит сырое `longpress`.
Соседние примитивы (`ValueRow.tsx`, `TimeWheel.tsx`) при этом сверяют `actionName`,
а `ServiceRows.tsx:191` — нет.

### P0-3. Каскад ест прайс, а алерт удаления врёт

Каскад — см. §0. Отдельно: алерт обещает

> «Записи, где она уже стоит, **не изменятся**».

Неправда **[код]**. Все 15 мест, читающих услуги, ходят через `useServices()`,
а он фильтрует `is_active = true`. Убранная услуга теряет имя везде:
`AppointmentSheet`, `CrewAppointmentSheet`, главный экран, лента клиента, «Топ услуг»,
генератор счёта — печатают заглушку **«Услуга»**.

Правка без миграции: отдельный селектор «все услуги, включая убранные» для
read-only-читателей имени. Фильтр по активности нужен **только** каталогу выбора
в записи.

### P0-4. Экран всегда открывается на первой бригаде — а у неё пусто

**[сим].** Календарь → шестерёнка → выбрал **Команду 2** → Справочники → «Услуги»
→ открылся прайс **Команды 1**. Пустой.

Причина **[код]**: `/calendar/services` реэкспортирует `ServicesScreen` =
`<ServicesList />` без `teamId`, поэтому `activeTeamId = teams[0].id`. Выбор в
ленте не запоминается между заходами.

На проде **teams[0] — это ровно та команда, у которой ноль услуг**: человек,
который только что назвал бригаду, получает чужой пустой прайс и делает вывод
«у меня нет услуг».

### P0-5. Пустой прайс — белая пустота на 1150pt

**[сим], скриншот `02-pustoy-prays.png`.** Заголовок «Услуги», лента команд,
**ничего**, кнопка внизу. `services.tsx` рисует там буквально `<View style={{flex:1}} />`.

Три состояния — «у этой команды нет услуг», «грузится», «сломалось», «нет связи» —

чей это прайс.

Довесок: пока грузится справочник команд, экран показывает кнопку **«Создать
бригаду»** владельцу, у которого три бригады.

## 2. Врёт тихо

### 2-1. Строка прайса молчит о лестнице
`A/C Cleaning` в списке — «30 мин · €50». На деле у неё «от 2 — €50 / 1 ч»,
«от 3 — €45 / 1 ч 30». Прайс, по которому цену диктуют по телефону, не показывает,
что у услуги есть цена от количества. Фраза для этого (`tierSentence`) уже написана
и на этом экране не используется.

### 2-2. Две колонки одной таблицы считаются ПО-РАЗНОМУ
Строка «от 3 · 45 · 1 ч 30 мин» читается как одно правило. В коде это два разных
механизма (`packages/shared/src/local/services.ts`):
- **Цена — ступенька.** `pricePerUnit` берёт последнюю ступень с `min_qty ≤ qty`.
  При 7 штуках и ступенях {2:50, 3:45} цена = 45, ровно.
- **Время — прямая между якорями и экстраполяция за последним.**
  `durationForQuantity` строит якоря (1,база), (2,60), (3,90) и считает **по наклону**.
  При 7 штуках выйдет 210 минут, которых никто не вводил.

Нигде на экране этого не сказано. Владелец думает, что задаёт одно правило дважды.

### 2-3. Пустая ячейка значит РАЗНОЕ в двух колонках
Валидация разрешает строку с ценой **или** временем. Молчание читается по-разному:
пустая **цена** → наследуется цена строки выше; пустое **время** → якоря нет,
прямая идёт **сквозь** эту строку. Визуально это одна и та же пустая клетка.

Хуже **[код]**: пустое время в таблице печатается как **«0 мин»**
(`readMinutes("") → 0 → durationLabel(0)`). Таблица обещает работу за ноль минут.

### 2-4. Новая строка приезжает с бессмысленным временем
`createTierDraft` сеет время как `база × количество`, игнорируя уже заведённую
лестницу. **[сим]**:

```
1     …    40 мин
от 2  50   1 ч
от 3  45   1 ч 30 мин
от 4  —    2 ч 40 мин     ← 40 × 4, хотя ряд шёл шагом 30 минут
```

Правильный сев — продолжить последним наклоном лестницы, ровно как считает
`durationForQuantity`. Этот же сев производит no-op'ы из §0.

### 2-5. Правка цены в прайсе — РЕТРОАКТИВНА

Самое важное последствие этой страницы, и на ней самой о нём не сказано ни слова.

`AppointmentSheet.tsx:440-455` при открытии сохранённой записи пересобирает её
строки через `buildServices` из **сегодняшнего** каталога. Оставить старую цену
строка может только если её когда-то правили руками (`pricePerUnit !== originalPrice`)
или услуга исчезла из каталога. Строка, которую никто не трогал, **переоценивается
по сегодняшнему прайсу** — вместе с сегодняшней лестницей.

Значит: поднял цену «Чистки» с €50 до €60 → любой, кто откроет майскую запись,
перепишет её деньги. На оплаченной записи это упирается в сторож
`protect_paid_appointment_finance` и требует возврата денег ради правки комментария.
Долг клиента на его карточке меняется от того, что кто-то заглянул в запись.

Это пункт 5 прошлого аудита («Замок: сохранённая строка записи не переоценивается»)
— не закрыт. Пока он открыт, **«поменять цену» на этой странице не является
безопасной операцией**, и любые удобства для правки цен (§4) делают дефект чаще.

### 2-6. Ступени из базы не округляются к пятиминутке
Базовая строка при открытии листа прогоняется через `roundToStep`, ступени —
нет **[код]**. Ступень в 47 минут покажет «47 мин», а барабан под ней — 45.
Та самая тихая ложь, от которой базовую строку уже лечили.

## 3. Дизайн и вид

### 3-1. Барабан ломает выравнивание таблицы
**[сим], скриншот `03-baraban-lomaet-plitu.png`.** Открытая ячейка красится в
`t.surface` — **белый, цвет самого листа**. Плита «Время на всё» визуально
распадается на две: подсвеченная строка выглядит дырой, у остатка появляются
закруглённые углы. Колонки «Кол-во» и «Цена» при этом остаются целыми — три
колонки перестают читаться как одна таблица, ровно вопреки закону ДС §5
«КОЛОНКА — ЭТО ПЛИТА». Плюс лист прыгает: барабан растит его на ~150pt и обратно.

Довесок: `scrollRef` доводит до глаза новую строку, но **не барабан** — раскрытый
у нижней строки, он остаётся под сгибом. Ref `rowTops`, заведённый ровно для этого,
пишется и **никогда не читается**.

### 3-2. Таблица сверстана впритык под один телефон
`QTY_W 104 + GAP 8 + MONEY_W 128 + GAP 8 + TIME_W 122 = 370pt`, доступно
`ширина − 2 × GUTTER`:

| Устройство | Доступно | Итог |
|---|---|---|
| iPhone SE / 13 mini (375) | 343 | **переполнение 27pt** — третья колонка режется |
| iPhone 17 (402) | 370 | ровно, нулевой запас |
| 17 Pro Max (440) | 408 | 38pt мёртвого поля справа |

Фиксированные ширины + `maxFontSizeMultiplier 1.2`: «1 ч 30 мин» на крупном
системном шрифте в 122pt не помещается, строка 56pt не растёт.

### 3-3. Разделители строк внутри плиты почти невидимы
Плита залита `t.fill`, разделители рисуются `t.surface` (белым) — контраст
около 1.13:1. Строк таблицы физически не видно; читается сплошной серый блок.

### 3-4. Ячейка не выглядит редактируемой и не показывает фокус
`CellInput` — без рамки, без ярлыка, **без фокусного состояния** [сим: после тапа
видны только системные маркеры выделения]. Ячейка времени при этом подсвечивается
синим и жирным, но и она ничем не показывает, что раскроет барабан (ни шеврона,
ни признака раскрывашки). Одна таблица — три разных языка обратной связи.
Размеры тоже не сходятся: «1» — 17pt, цена — 16pt, время — 17pt.

### 3-5. Барабан «00 : 30» читается как время суток
Колонки без подписей «ч» / «мин», между ними двоеточие. В листе про цены `00 : 30`
честно похоже на полпервого ночи. Подпись живёт только в `accessibilityLabel`.

### 3-6. Цвет: 40 вариантов ради точки 12pt
Палитра раскрывается прямо из строки имени, и её мишень стоит **перед** текстом
(x ≈ 43pt против 62pt) — палец, идущий править название, попадает в палитру.
Последний ряд почти белый: такая точка на белой строке невидима. Варианта «без
цвета» нет. На проде 3 услуги из 6 стоят с дефолтом — выбором никто не пользовался,
и колонка точек в списке несёт ноль информации.

### 3-7. Мелочи, каждая по одной строке
- Корзина в шапке листа: `ICON.sm 18` + `hitSlop 8` = **34pt**, минимум по HIG — 44.
  Она же — единственное опасное действие листа.
- «＋ Добавить» — мишень ~30pt и слово без предмета.
- Заголовок листа правки — «**Услуга**». Не говорит ни какая, ни чьей команды.
- «＋ Описание» **открывается, но не закрывается**: `hasDescription` обратно не снимается.
  Кнопка называется «＋ Описание», а созданный блок — «Описание в счёте».
- Описание собрано рукописным `TextInput` вместо примитива `Field` и держится на
  подпорках `marginTop: -6 / -8`.
- Две двери — **два подзаголовка одной страницы**: «Каталог работ и цены» (Кабинет)
  и «Каталог работ, цены и длительность» (Календарь).
- Тап по скриму / свайп вниз закрывает лист **молча**, унося набранное. Снять
  цифровую клавиатуру больше нечем — «Готово» над ней нет.
- «Сохранить» активна всегда, даже когда ничего не менялось; повтор после сетевой
  ошибки заводит вторую такую же услугу.
- Высота строки: `ROW_H = 60` в услугах против «высота от 56» у `SettingsRow` в ДС §5.
- Ручка перетаскивания стоит в каждой строке постоянно и уезжает вместе со строкой
  при свайпе, налезая на цену.
- **На третьей двери (`/cabinet/teams/[id]/services`) перетаскивания нет вовсе**
  [код]: `rangeFor` возвращает `[index, index]`, `draggable = max > min` → ручка не
  рисуется. Объяснения на экране нет.

## 4. Экономика тапов

Считано по живому маршруту.

| Работа | Сейчас | Куда можно |
|---|---|---|
| Дойти до прайса (Кабинет) | 2 тапа + прокрутка | — |
| Дойти из Календаря | 2 тапа | — (но приводит не в ту команду, P0-4) |
| Завести первую услугу | **8**: Услуги → чип → «Создать» → имя → тап цены → **тап на каждую цифру** → тап времени → прокрутка → «Создать» | **5** |
| Поменять цену на €5 | **6** | **4** |
| Поменять 30 мин на 45 | **7** (три щелчка барабана) | **4** с пресетами |
| Завести лестницу на 3 ступени | **~18** | **~10** |
| Убрать одну ступень | долгое нажатие, работающее на трети строки | **1** тап по крестику |
| Дубль услуги | свайп вправо → «Дубль» → выделить имя целиком → набрать → «Создать» | то же, имя выделено сразу |
| Найти услугу в прайсе из 40 | ~4 экрана прокрутки, поиска нет | 1 тап + набор |
| Завести прайс второй бригаде | заново, N × 8 тапов | 2 тапа «скопировать» |

**Три правки дают почти всю экономию:**
1. Починить P0-1 — минус 1–3 тапа на каждое число, на каждой услуге, навсегда.
2. Панель над цифровой клавиатурой с «Далее»: имя → цена → время без возврата
   пальцем к ячейкам. У `decimal-pad` на iOS нет Return, поэтому сейчас каждая
   ячейка стоит отдельного тапа, а закрыть клавиатуру можно только слепым тапом.
3. Ряд пресетов времени рядом с барабаном («15 · 30 · 45 · 1 ч · 1 ч 30 · 2 ч»).
   **Требует решения владельца** — см. вопрос 1.

одной строкой — ровно как владелец и просил. Закон ДС §5 не переписываем: там сказано, чем
время ВЫБИРАЮТ, и барабан остаётся этим чем.

**2. Время в лестнице — ОСТАЁТСЯ НАКЛОНОМ. Решение моё, владелец отдал его мне («делай»).**
Причина, по которой две колонки обязаны считаться по-разному, — они меряют разное:
- «Цена за **одну**» — за штуку. Ступенька вниз на пороге, но итог `цена × количество`
  всё равно растёт с количеством. Ступенька здесь ничего не замораживает.
- «Время **на всё**» — итог. Сделай его ступенькой — и семь блоков займут те же 1 ч 30 мин,
  что и три. Это неправда про физический труд, и календарь будет держать бригаду свободной
  тогда, когда она в работе.

Значит арифметику не трогаем — трогаем то, что вокруг неё врёт:
- пустая ячейка времени перестаёт печататься как «0 мин» (2-3);
- новая строка сеется ПРОДОЛЖЕНИЕМ наклона лестницы, а не `база × количество` (2-4).
Пояснительной строки под таблицей не заводим — она запрещена законом от 2026-08-21
(«внизу не нужно писать»). Подписи колонок «за одну» против «на всё» и так говорят разницу.

**3. Цена в прайсе — ВСЕГДА БЕЗ НДС.**
Владелец: «цены всегда без НДС на услуги; НДС будет считаться в самой записи, когда сам будет
выбирать — с НДС или без НДС». У услуги НЕТ и не будет своей ставки и своей галки. Налог живёт
в одном месте на весь продукт — три клавиши на операции. Записано законом в
`apps/mobile/docs/DESIGN-SYSTEM.md`. Кода это не меняет: подпись «Цена за одну, €» уточнения
«без НДС» НЕ получает — уточнение нужно там, где есть выбор, а здесь выбора нет.

**4. Цвет услуги — ОСТАЁТСЯ 40 ВАРИАНТОВ.**
Владелец: «да, 40 пусть будет». Палитру не сужаю. Из пункта 3-6 остаётся в работе только то,
что не про количество цветов: мишень цвета не должна перехватывать палец, идущий править имя.

**5. Копирование прайса между бригадами — БЕРУ. Решение отдано мне.**
На проде две команды из трёх с пустым прайсом, и это единственная идея из списка, которая
экономит десятки тапов уже сегодня. Денег записи не касается вовсе — заводит новые строки
справочника, — поэтому замка из волны 2 не ждёт. Остаётся в волне 3 как добавление, а не
починка: сперва чиним, потом добавляем.


## Приложение: вне этого захода

Найдено попутно, касается записи и счёта, а не страницы услуг. Записано, чтобы не потерять:

- Каталог услуг в листе записи из календаря **не сужен до бригады записи** —
  закон «услуга принадлежит одной команде» соблюдён только в одной двери из двух.
- Быстрое создание услуги из записи (`InlineServiceCreate`) пишет **цену 0**
  (`parseMoneyInput("") → 0`) — в обход закона «пусто — это не ноль», который
  специально завели в большом листе. Две двери создания услуги, два разных закона.
  *(Смежная догадка — «она садится нулевой позицией поверх прайса» — проверена и
  отвергнута: этот блок показывается только при ПУСТОМ каталоге, так что перебивать
  ему нечего.)*
- Подвал каталога услуг считает свою сумму, не зная ни количеств, ни лестницы.
- `appointments.total_duration` пишется двумя экранами и не читается ни одним.
- 6 колонок `services` без писателя: `category_id`, `available_weekdays`,
  `online_enabled`, `material_costs`, `brigade_ids`, `cost_per_unit`
  (у последней есть живой читатель, который поэтому всегда показывает ноль).
