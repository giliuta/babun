# Календарь — глубокий аудит 2026-07-14

**Метод:** мультиагентный аудит (110 агентов): 8 параллельных аудиторов по срезам → адверсариальная верификация каждой находки скептиком → критик полноты. Каждая цифра ниже — подтверждена повторным чтением кода.

**Объём:** `app/(dashboard)/index.tsx`, все 18 файлов `src/features/calendar/`, `AppointmentSheet.tsx`, `cabinet/calendar.tsx` (настройки), shared-слой (`local/appointments`, `sync/appointmentsCached`, `expand-repeat`, `date-utils`), эталон — `apps/web/src/components/calendar`.

**Итог:** 101 сырая находка → 9 отклонено верификаторами → **92 подтверждено + 5 от критика**. После склейки дублей: **2×P0, 9×P1, ~20×P2, ~55×P3**. Карта из ~210 интерактивных элементов — в Приложении А (подавляющее большинство ✅).

**Вердикт:** каркас страницы зрелый — якорь даты един для всех видов, повторы правильно маршрутизируются на seed, long-press меню + Undo работают, роуты существуют. Главные болезни: (1) **деньги** — быстрая оплата не доходит до финансов, (2) **CTA-тупики** — оба «денежных» призыва ведут на экран, где нужных записей не бывает, (3) **запятая** в денежных полях молча обнуляет суммы, (4) **настройки** — экран не скроллится и часть настроек мертва.

### P2 — UX, паритет, скрытые баги

**Деньги/данные**
- «Скрывать отменённые» меняет финансовые итоги дня (футер/месяц/модалка) — фильтр отображения должен влиять только на сетку. `index.tsx:420`
- Автоскидка лояльности навешивается при каждом ОТКРЫТИИ сохранённой записи → ложный «Сохранить изменения?» и молчаливая уценка. `AppointmentSheet.tsx:385`
- Запятая в поле скидки молча отключает скидку. `AppointmentSheet.tsx:1037`
- Дробную цену услуги невозможно ввести (controlled `String(price)` съедает разделитель). `AppointmentSheet.tsx:938`
- Слой чтения глотает ошибки сервера при холодном кэше → пустая сетка «свободного дня» вместо error-экрана (риск дабл-букинга). `sync/appointmentsCached.ts:96`
- `patchToRow` не переносит `event_*` поля в офлайн-очередь — офлайн-правки событий сотрутся при реплее. `sync/appointmentsCached.ts:437`
- `getCurrentCyprusTime` жёстко UTC+3 — зимой фолбэк-«сейчас» врёт на час. Фикс: `getCurrentTimeInZone("Europe/Nicosia")`. `date-utils.ts:129`
- Гонка быстрых тапов степпера настроек (параллельные однополевые upsert'ы). `local-settings.ts:75`
- Гонка «Сегодня» против догоняющего коммита свайпа — прыжок даты может перезаписаться на ±1 день. `pager.tsx:126`

**Тупики и недостающие пути**
- Нет пункта «Перенести» в long-press меню (web RescheduleSheet) — в Списке/Месяце перенос невозможен вообще. `index.tsx:707`
- «Финансы дня» read-only: day extras (ручной доход/расход) с телефона не создать — только смотреть заведённое на вебе. `DayFinanceModal.tsx:15` + нет мутации в `queries.ts:126`
- Букинг с карточки клиента в чужую бригаду: запись создаётся, календарь остаётся на старой команде — «запись пропала». `index.tsx:298`
- `?new=` не принимает `services=`/`kind=` — «Повторить заказ» и deep-link события с карточек невозможны. `index.tsx:293`
- Пустой каталог услуг = тупик первой записи: пикер — белый лист, «Создать» серая без объяснений. `AppointmentSheet.tsx:1321`
- Нет поля адреса в шите — клиент без объектов едет с `address=""` (жёлтый «нет адреса»), бригада не знает куда. `AppointmentSheet.tsx:603`
- Нет UI повтора для событий — повторяющееся событие можно завести только с веба. `AppointmentSheet.tsx:560`
- Телефон клиента в шите — мёртвый текст, позвонить нельзя (веб умеет). `AppointmentSheet.tsx:765`

**Поведение**
- Удаление/отмена повторяющейся записи гасит ВСЮ серию, а подтверждение молчит о повторах. `AppointmentSheet.tsx:686`
- Футер «Буфера» обещает блокировку брони, но буфер чисто визуальный — согласовать текст или поведение. `cabinet/calendar.tsx:313`
- Мини-календарь при повторном открытии показывает пролистанный в прошлый раз месяц, а не текущий. `MiniCalendar.tsx:39`
- VoiceOver не видит содержимое трёх поповеров шапки (меню вида, мини-календарь, пикер метки) — по одному `accessible={false}` на подложки. `ViewModeDropdown.tsx:66` и соседи

## Рекомендуемые волны правок

1. **Волна «Деньги»** (P0 №1 + P1 №3, №4, №5 + P2 hide_cancelled/финансы): быстрая оплата пишет полный платёжный набор на сумму долга; оба CTA ведут в close-day; финансовые итоги не зависят от фильтра отображения. Это самое опасное — владелец теряет учёт дохода.
2. **Волна «Настройки»** (P0 №2 + P1 №10, №11 + P2 степпер-гонка, футер буфера): скролл, каскад, оживить/убрать мёртвую настройку.
3. **Волна «Запятая и формы»** (P1 №8 + P2 скидка/цена/лояльность/серия-подтверждение): денежный ввод с запятой везде, автоскидка только при смене клиента, честное подтверждение для серий.
4. **Волна «Навигация»** (P1 №6, №7 + P2 team-switch при букинге, `?new=` расширение, «Перенести», мини-календарь): все переходы приземляются туда, куда обещают.
5. **Волна «Паритет+»** (P2 day extras, адрес в шите, повтор событий, звонок из шита, error-проброс чтения, `event_type_id` решение, Кипр-таймзона, a11y поповеров) + выборочно P3.

## Приложение А. Карта взаимодействий (каждая кнопка)

### Оркестратор (index.tsx)

Срез — корневой оркестратор вкладки «Календарь»: единый якорь даты для всех четырёх видов (день/неделя/месяц/список), персист mode+team в MMKV, бизнес-таймзона с минутным тиком, экспансия повторов в окно −30/+60 дней, first-run гейт и онбординг-карточка, два ActionSheetIOS-меню (контекстное и оплата) с Undo-тостами, deep-links ?new=/?date= и корректная react-query-инвалидация через общий ключ [appointments] (мутации дополнительно инвалидируют transactions/clients/accounts только при денежных патчах). Архитектура зрелая: якорь даты не рассинхронизируется, виртуальные вхождения повторов правильно маршрутизируются на seed, findOverlap вызывается и на drag (warn-only), и внутри шита при создании/правке, все переданные пропсы детьми потребляются, все роуты назначения существуют. Главные дефекты — не мёртвые кнопки, а кнопки, ведущие не туда: оба «денежных» CTA (пилл «без оплаты» и EndOfDayBanner) шлют на /cabinet/unclosed, где рекламируемых записей по определению нет (web ведёт в finances/close-day), «Отметить оплату» пишет платёж на полный total без учёта предоплаты (задвоение дохода, дефект унаследован с веба), а ?date=-переходы с карточек клиента/мастера теряют команду — визит чужой бригады открывается пустым днём. Из паритета с вебом не хватает пункта «Перенести», long-press меню в «Списке» и параметров services=/kind= в ?new=; остальное — полировка (мёртвый isSameDay, стейл dismiss баннера через полночь, фикс UTC+3 в fallback-таймзоне).

Архитектурно всё крепко: единый якорь даты через setDay согласован между всеми видами, все три money-потребителя считают через общий computeDayFinance (footer=modal=month расходиться не могут между собой), day extras читаются из Supabase, пейджер недели/месяца живой и без миганий, a11y на сетках выше среднего. Главные дыры — не в подсчётах, а в проводке CTA: обе «денежные» кнопки среза (пилюля «N без оплаты» и «Открыть» вечернего баннера) ведут в /cabinet/unclosed, чей фильтр (прошлые scheduled) по построению не может содержать посчитанные записи (completed с долгом) — при том что правильный экран /cabinet/close-day уже существует. Вторая системная проблема: hideCancelled вшит в visibleAppts и потому дисплейный тумблер меняет финансовые итоги (web считает деньги без него), а модалка финансов read-only — на мобильном вообще негде завести ручной доход/расход дня, хотя итоги их учитывают. Остальное — полировка: несброс dismiss-флага баннера через полночь, pop-in повторов на соседних страницах месяца, отсутствие long-press меню в Agenda и пара a11y/perf мелочей.

### Форма записи (AppointmentSheet)

AppointmentSheet — модальная форма создания/редактирования записи и события, открывается с календаря (тап по слоту → create с дефолтами слота/команды, тап по записи → edit; виртуальные вхождения повторов календарь маппит на seed). Архитектура добротная: offline-aware мутации с оптимистикой и точечной инвалидацией финансов, умные дефолты (недавние клиенты, последняя команда, частые услуги), веб-паритетные механики (grow-only конец, bulk-ladder цены, автоскидка лояльности, overlap-warning, dirty-close guard, оплата остатка при «Выполнено»). Главные дефекты — класс «немой потери денег/данных»: запятая как десятичный разделитель превращает сумму в 0 и гасит скидку (P1/P2), controlled-инпут цены съедает десятичную точку, автоскидка лояльности мутирует цену уже сохранённой записи при простом открытии и порождает ложный «Сохранить изменения?». Паритетные дыры против веба: телефон не звонит (нет tel:/Linking), нет поля адреса/заметки к адресу, нет UI повтора событий (event_repeat) при том что календарь повторы уже разворачивает, удаление/отмена seed повторяющегося события стирает серию без предупреждения. Мёртвых кнопок нет; всё остальное доведено до мутаций и корректной инвалидации.

### Слой данных и синхронизация

Слой данных календаря устроен добротно: чтение идёт через SWR-обёртку (sqlite-кэш мгновенно + фоновая ревалидация + realtime/revalidate-мост в react-query), записи — через offline-first обёртку с атомарной очередью и грамотным реплеером (updated_at-sentinel, force-fallback, прощение дубль-insert'ов), пагинация обходит 1000-строчный кап PostgREST, UUID-гварды закрывают Hermes-специфику, а двойной тап сохранения отсечён isPending/disabled. Главные дыры не в архитектуре, а на стыках: quick-действие «Отметить оплату» завершает запись без payment_status='paid', из-за чего серверный триггер дохода не создаёт строку в финансах (P0 — финансы врут); event_type_id пишется UI, но не существует в БД и отбрасывается всеми мапперами (P1 — тихая потеря выбора типа события); patchToRow офлайн-очереди теряет все event_*-поля; фолбэк «кипрского времени» зашит на UTC+3 и зимой врёт на час; ручные строки дохода/расхода дня на мобиле read-only против редактируемого веба. Остальное — точечные P3: гонка отката оптимистичного апдейта, окно исчезновения офлайн-созданной записи до реплея, ложные предупреждения о пересечении с событиями в шите и edge «until раньше seed» в движке повторов.

### Настройки календаря

Экран «Кабинет → Календарь» (apps/mobile/app/(dashboard)/cabinet/calendar.tsx) — глобальные настройки календаря с instant-commit: каждый контрол шлёт однополевой патч через useSaveCalendarSettings (MMKV-кэш + upsert в Supabase calendar_settings), а календарь (app/(dashboard)/index.tsx) читает те же данные через общий query-ключ, поэтому почти все настройки применяются мгновенно без перезапуска. Живые и корректно подхватываемые: видимое окно (start/end), «Открывается на», шаг сетки (снап тапа/драга + дефолтная длительность), буфер (серые полосы), «Скрывать отменённые» — все с правильным приоритетом командных оверрайдов, как на вебе. Два тяжёлых дефекта: экран не скроллится (нижние секции физически недостижимы — Switch «Скрывать отменённые» не дотянуться) и секция «Рабочие часы по умолчанию» мёртвая — DayView берёт wash только из расписания команды, а useTeamSchedule всегда коалесцирует отсутствующее расписание в зашитый DEFAULT_SCHEDULE 08–22, так что глобальная настройка не влияет ни на что. Плюс отсутствует веб-каскад клампов при патче (можно сохранить противоречивое состояние, которое офлайн-санитайзер молча откатывает), а «первый день недели» и таймзона на мобильном не редактируются (weekStart при этом мёртв и на вебе — вся веб-страница настроек спрятана за выключенным флагом PERSONAL_CALENDAR_ENABLED).

### Паритет с вебом

Мобильный календарь — добротный порт веб-эталона: все 4 вида (День/Неделя/Месяц/Список; «3 дня» удалён сознательно), живой пейджинг за пальцем, фокальный пинч-зум, чипы команд, метки дней с тинтом колонок, окно часов/расписание/перерывы/буферы per-team, повторы событий с защитой виртуалов, финансовый футер+модалка+месячные мини-суммы из одного computeDayFinance. Ключевой контекст подтверждён: long-press меню записи РЕАЛИЗОВАНО (нативный ActionSheetIOS, index.tsx:668) и Undo РЕАЛИЗОВАН (toast-action на статус/отмену/удаление/оплату) — записи в памяти о «планируется» устарели. Мобильный местами лучше веба: «Позвонить»/«Маршрут» в меню, оплата «Переводом» (веб только cash/card), pull-to-refresh/скелет/error-retry, «сейчас» и просрочка в бизнес-таймзоне (веб-бейдж Clock считает по времени устройства), a11y-actions переноса, свайп месяца (у веба месяц без свайпа). Главные дыры паритета: P1 — снятие метки дня сломано для команд с default_city и веб-сентинел «__NONE__» светится как метка (мобильный не знает v693-протокол); P2 — нет «Перенести» в меню (перенос на другой день только правкой даты в шите), и «Финансы дня» read-only (day extras вообще не пишутся с телефона, нет сегмента «Ожидается»). SpecialScheduleModal и RepeatCopyModal недостижимы и на самом вебе (сеттеры не вызываются) — не считаются гэпами.

Проверил пять слабо покрытых зон: обработку ошибок чтения/мутаций (глобальный MutationCache + meta.errorHandled — контракт выдержан во всех колл-сайтах календаря, но read-слой глотает онлайн-ошибки — новая P2), пустые данные первого запуска (клиент создаётся inline, а услуги — тупик, новая P2), полуночную арифметику слотов, таймеры/утечки (setInterval в index.tsx единственный и чистится; в фичах календаря таймеров нет) и кросс-таб проводку (создание клиента из шита инвалидирует ["clients"], денежные патчи — transactions/clients/accounts — чисто).
