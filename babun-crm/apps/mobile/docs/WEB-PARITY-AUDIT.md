## Fix-first bugs
| Area | Effort | Bug |
|---|---|---|
| calendar | L | Recurring appointments are not expanded into occurrences on the grid. Web builds expandedAppointments via expandRepeat over a −30/+60-day window so an event_repeat rule paints on every occurrence (page.tsx L891-912). Mobile renders raw appts straight from useAppointments with no expandRepeat, so a repeating booking/event created via RepeatReminderSheet only ever shows on its seed date — occurrences silently vanish from day/week/month/agenda. |
| clients-list | M | No quota awareness on client creation. Web gates the «+» add button on tenant quota (clientsAtCap → toast + analytics + QuotaBanner, page.tsx lines 151-157, 781-793, 810-817). Mobile's «+» and new.tsx have no quota check or at-cap banner, so an over-limit tenant hits a server error instead of a graceful nudge. |
| client-create-import | M | Create screen has no country selector. Web /clients/new uses CountryPhoneInput with a flag picker and passes the chosen country into tryToE164(trimmedPhone, country) (clients-99 F2.7 explicitly killed the hardcoded +357). Mobile app/(dashboard)/clients/new.tsx uses a plain phone-pad TextInput and calls tryToE164(phone.trim()) which defaults to CY. For any non-Cyprus tenant entering a local-format number (e.g. a Russian '8...' or a GR local number without '+'), the E.164 the mobile create screen computes — and therefore the dedup key AND the stored phone_e164 — silently normalize under the wrong country, diverging from what web would produce. Babun is sold as multi-country SaaS, so this is a real behavior gap for non-CY tenants, not just cosmetics. |
| client-create-import | S | Import upload has no size/row guardrails. Web UploadStep.tsx enforces MAX_BYTES=10MB, MAX_ROWS=5000, empty-file and .csv/.txt extension checks, each with a specific RU error message before parsing. Mobile ImportWizardSheet.pick() parses whatever the DocumentPicker returns with no cap, and useImportRows chunks all rows at CHUNK=10 sequential round-trips. The upload copy claims «До 5000 строк за раз» but nothing enforces it: a 20k-row file loads fully into memory (character-scan parser) and fires ~2000 sequential insert batches — slow, memory-heavy, and un-cancellable — instead of being rejected up front like web. |
| chats | M | Mobile never renders image messages — it only shows the text placeholder '📷 Фото'. Web renders the actual image bubble (<img src={msg.photo} …> at page.tsx:729) and the list preview treats content_type==='image' OR msg.photo as a photo (page.tsx:372). Mobile MessageRow (bodyOf, [id].tsx:88-92) returns the literal string '📷 Фото' for both list and thread and has no <Image> anywhere, so an inbound WhatsApp/IG photo shows as text only and the image is invisible. This is a real data-loss gap for any chat containing photos (seed data has none, so it's easy to miss). |
| teams | M | Brigade services DELETE is destructive across all teams. Web teams/[id]/services `removeFromBrigade` only strips the current team from `service.brigade_ids` when the service is shared (`usedElsewhere`), keeping it live for other brigades; it only fully deactivates when this is the sole/legacy-all brigade. Mobile services.tsx `handleDelete` calls `del.mutateAsync(id)` (global soft-delete via useDeleteService) unconditionally, ignoring `teamId`. Removing a shared service from one brigade's list wipes it from every brigade. |
| reference-screens | S | Object-types & event-types & categories — inconsistent delete UX vs web/other mobile screens. Web guards city/label/loyalty deletes with a descriptive useConfirm dialog («ссылка останется в записях…»). Mobile object-types.tsx and event-types.tsx delete on a single Trash2 tap with NO confirmation at all (categories/cities/loyalty/inventory do use Alert.alert). This is an accidental one-tap data loss on two of the seven screens. |
| recurring | S | Reminder note is written but never shown on mobile. Web RecurringCard renders item.note with a StickyNote icon (recurring/page.tsx:246-251). The auto-seed path on mobile DOES capture and store a note (AppointmentSheet.tsx:959-970 → RepeatReminderSheet passes note into createRecurringReminder), but the mobile inbox card renderReminder (recurring.tsx:145-223) never displays item.note. Any note the dispatcher typed on 'Повторить через…' is invisible in the inbox — the whole point of the note (e.g. 'проверить пульт') is lost. |
| sms | S | Mobile onboarding copy (apps/mobile/app/(auth)/onboarding.tsx line 75) instructs the user: 'Настройки → Автоматические SMS. Возвраты за 24 ч / 2 ч до визита.' — but that screen does not exist anywhere in the mobile app, so the instruction dead-ends. |
| insights | S | KPI delta computation edge case must be ported faithfully, not naively. Web deliberately returns null (no chip) when the previous period is 0 or the ratio is non-finite (toDeltaPct + the +Infinity sentinel logic, per the v686/Audit-2026-05-21 P1-2 fix comment at page.tsx lines 392-402). A mobile reimplementation that shows '↗ 999%' or 'Infinity%' when there's no prior-period baseline would be a regression versus web. |
| auth-onboarding | M | Signup email-confirmation deep link has no in-app handler. Web routes the confirmation link through /auth/callback (route.ts) which calls verifyOtp({type}) to establish a session and drop the user straight into the app. On mobile the supabase client sets `detectSessionInUrl:false` and the ONLY deep-link parser is reset-password.tsx (recovery tokens only) — a `type=signup` confirmation link opened on the device is not caught by any screen, so the user cannot be auto-signed-in from the link and must return to /login and re-enter their password. ## Per-area detail
### calendar — PARTIAL
Mobile calendar has strong core parity: day/3-day/week/month/agenda modes, pinch-zoom, tap-empty-slot create, drag-reschedule (within a day), single-active-team chips, first-run gate, now-line in business timezone, per-day finance footer, MiniCalendar jumper, hideCancelled filter, all-day left strips, overlap layout, red weekends. Gaps are all secondary dispatcher workflows layered on the web grid: no long-press quick-action menu (copy/quick-status/pay/reschedule-to-another-date), no per-day city/label chip+picker+day-tinting, footer tap opens the day instead of a day-finance breakdown modal, recurring appointments are never expanded into occurrences, and buffer-band rendering plus the morning/end-of-day briefings and day-summary strip are absent.

- **[feature/L]** No long-press quick-action menu on an appointment block. Web long-press opens ActionMenuModal with Копировать (duplicate → opens the copy for edit), quick-status (Выполнена/В работе/Вернуть в план), Отметить оплату, Перенести, Отменить/Восстановить, Удалить — all one-tap with an UndoToast. Mobile tap opens the full edit sheet and long-press only starts a vertical drag; status/pay/delete are reachable only by opening the sheet, and Копировать (duplicateAppointment) plus quick reschedule are not reachable at all. This is the dispatcher's fastest daily path (page.tsx L1747-1802, ActionMenuModal.tsx).
- **[bug/L]** Recurring appointments are not expanded into occurrences on the grid. Web builds expandedAppointments via expandRepeat over a −30/+60-day window so an event_repeat rule paints on every occurrence (page.tsx L891-912). Mobile renders raw appts straight from useAppointments with no expandRepeat, so a repeating booking/event created via RepeatReminderSheet only ever shows on its seed date — occurrences silently vanish from day/week/month/agenda.
- **[feature/L]** Per-day city/label chip is missing. Web DayColumn header renders a tappable, city-colored short label pill (ПАФ/ЛИМ/custom tags) that opens CityPickerModal to set team.day_cities per date, and tints the whole day column by that label color when team.tint_days_by_label is on (DayColumn.tsx L311-360, page.tsx onCityTap/CityPickerModal). Mobile day/week headers show only weekday+number+presence-dot: no label display, no picker, no tint. tint_days_by_label is even editable in mobile team settings (cabinet/teams/[id]/cities.tsx) but has zero effect on the grid.
- **[feature/L]** Day-finance footer tap goes to the wrong destination. Web footer tap opens DayFinanceModal — a payment-method breakdown, completed-services list, and manual income/expense entry for that day (page.tsx L2270-2296, DayFinanceFooter onDayTap). Mobile footer onTapDay just calls pickDay → switches to Day view (index.tsx L556, DayFinanceFooter). There is no day-finance detail/entry modal, so per-day expense entry and the paid-method breakdown are unreachable from the calendar.
- **[feature/M]** Buffer-time bands are not rendered. Web DayColumn paints a grey buffer band of team.buffer_minutes after each live appointment so back-to-back slots visibly reserve travel/cleanup time (DayColumn.tsx L558-575; page.tsx effectiveBufferMinutes). Mobile DayColumn takes no bufferMinutes prop and draws nothing — buffer_minutes is editable in mobile team settings (cabinet/teams/[id]/index.tsx L605) but has no visual effect on the calendar.
- **[feature/L]** Morning / end-of-day briefings and the day-summary strip are absent. Web mounts MorningBriefing (06:00-10:00 daily brief), EndOfDayBanner (unpaid nudge → close-day), and a DaySummaryStrip in day view (records/earnings/unpaid, tap → finances) (page.tsx L1903-1910, L2373-2400). Mobile has none of these ambient summaries; the day view shows only the grid + finance footer.
- **[feature/M]** Copy/duplicate an appointment has no entry point on mobile. Web exposes duplicateAppointment via both the long-press menu (Копировать) and RepeatCopyModal (duplicate N times at a cadence with an undo) (page.tsx L1784-1791, L2241-2252). Mobile has neither the single-copy action nor the repeat-copy modal, so re-booking a similar visit means re-entering everything by hand.
- **[feature/M]** Reschedule-to-another-date flow is missing. Web RescheduleSheet lets the user move an appointment to a different date/time via a sheet (reachable from the long-press menu and from inside the edit sheet's onReschedule) (page.tsx L2379-2393). On mobile, drag only shifts an appointment vertically within the same day column (Block.commit uses translationY only), so moving a booking to a different day requires manually editing the date field in the sheet — no dedicated reschedule affordance.
- **[feature/M]** No special-schedule (single-day working-hours override) modal. Web SpecialScheduleModal (opened via day-header context menu) overrides a team's working hours for one date, repainting the off-hours wash (page.tsx L2231-2238, onDayHeaderTap). Mobile has no way to set a one-off schedule for a specific day.
- **[polish/S]** Fresh-tenant onboarding card is absent on the grid. Web shows CalendarOnboardingCard (client→service→appointment steps) when the tenant has 0 clients + 0 services + 0 appointments, plus a floating CalendarEmptyState 'Добавить первую запись' over an empty grid (page.tsx L2025-2064). Mobile's calendar has only the first-run 'create calendar' gate and the agenda-mode empty state; a team-created-but-nothing-else tenant lands on a bare grid with no guided next step.

_Notes: Excluded from gaps (intentional/parity): root-tab create via tap-empty-slot (no FAB) — canonical; single active-team calendar, no 'all teams' view — matches web Header; red Sat/Sun weekends — locked; light-only — locked; offline SWR cache/paging — mobile advantage; personal calendar tab — parked on web behind PERSONAL_CALENDAR_ENABLED flag, so its absence on mobile is parity not a gap; desktop keyboard shortcuts + mouse DnD (page.tsx L1416-1516) — desktop-only, N/A on touch; DND a11y RU announcements — desktop DnD only. Cross-day drag is NOT a gap: web disables touch drag entirely (MouseSensor only) and mobile has no cross-column drop, so both platforms require the sheet/reschedule flow to change the date. Mobile actually adds value over web here: pinch-zoom and vertical drag-reschedule work on touch where web's are mouse-only. The AppointmentSheet on mobile does cover status change, payment capture, cancel-with-reason, and hard-delete inside the edit screen — so those capabilities exist; the gap is specifically the fast long-press context menu + copy + reschedule-sheet, not the underlying operations. Verified mobile DayFinanceFooter reads day extras and computeDayFinance identically to web (earned-vs-planned contextual income), so the footer numbers themselves are at parity — only the tap target differs._

### clients-list — PARTIAL
The core list, search, filter panel, sort, and bulk-select flows are a faithful 1:1 port of the web (identical predicate order, pinned-first comparator, 4 sort keys, contextual facet counts, period presets/custom range, active-token bar, bulk delete/SMS with linked-appointment detach). Mobile even adds CSV export to the bulk bar (advantage) and routes to the canonical /clients/[id] card everywhere, so the web ?id= deep-link intermediary is correctly unneeded. The parity delta is concentrated in per-row quick actions and proactive nudges: mobile's long-press is repurposed to enter selection mode, so it loses the web's pin / book / remind / delete swipe+context-menu actions and the phone-channel picker; and the reactivation strip, birthday-week strip, CSV-import hint, quota gating, and first-run tutorial are all absent.

- **[feature/M]** Row swipe actions are shallower than web. Web ClientCard: left-swipe = Закрепить/Открепить (pin toggle), right-swipe = Записать / Напомнить / Удалить (SwipeableRow in page.tsx lines 1029-1071). Mobile ClientRow (index.tsx lines 257-283) only renders a single right-swipe «Позвонить» that duplicates the tap-to-call button. No pin, book (Записать), remind, or delete is reachable from a list row on mobile.
- **[feature/M]** No per-row long-press quick-actions menu. Web long-press opens a ContextMenu (Сообщение / Звонок / Открыть карточку / Выбрать несколько / Закрепить / Напомнить / Удалить — page.tsx lines 1219-1279). Mobile repurposes long-press to ENTER selection mode (index.tsx onLongPress → enterSelection), so all those per-row shortcuts are gone; the only way to book/remind/pin/delete one client is to open the full card.
- **[feature/S]** No way to pin/unpin a client from the list. Both apps sort pinned_at first and render the pin glyph, but mobile only READS pinned_at — there is no togglePin UI (web offers it via left-swipe and context menu). A pinned client can never be unpinned from mobile's list.
- **[feature/M]** No reminder-setting path from the list. Web sets client.reminder_at via the swipe «Напомнить» + ReminderPicker presets (page.tsx setReminder, lines 491-494, 1282-1291). Mobile list has no reminder affordance at all.
- **[feature/M]** Reactivation nudge widget missing. Web renders ReactivationWidget above the search when ≥1 client is silent (90+ days): «N клиентов не были 90+ дней» with a «Показать» filter shortcut AND a one-tap cohort-SMS blast that pre-selects every silent client (page.tsx lines 824-847). Mobile computes segmentCounts.silent but never surfaces the nudge or the cohort-SMS shortcut; «Давно не были» is only a buried filter segment.
- **[feature/S]** Birthday-this-week hero strip missing. Web shows a tappable «N ДР на неделе» strip (birthdayThisWeek>0) that jumps to the birthday segment (page.tsx lines 915-935). Mobile computes birthdayInDays but renders no such strip on the list.
- **[feature/M]** Phone-channel quick-actions picker missing. Web long-press on the green phone icon opens ClientQuickActionsSheet (Звонок / WhatsApp / SMS / Telegram) (page.tsx quickActionsFor). Mobile's phone button and swipe only fire a bare tel: link — no WhatsApp/SMS/Telegram channel choice from the list.
- **[polish/S]** CSV-import onboarding hint missing. Web renders CsvImportHint when 1 ≤ clients < 5 to nudge bulk import (page.tsx line 820). No equivalent on the mobile list (import is only reachable via the settings screen).
- **[bug/M]** No quota awareness on client creation. Web gates the «+» add button on tenant quota (clientsAtCap → toast + analytics + QuotaBanner, page.tsx lines 151-157, 781-793, 810-817). Mobile's «+» and new.tsx have no quota check or at-cap banner, so an over-limit tenant hits a server error instead of a graceful nudge.
- **[polish/S]** First-visit tutorial overlay missing. Web shows a TutorialOverlay pointing at «+» for zero-client tenants (page.tsx lines 708-714). Mobile has no onboarding pointer.
- **[polish/S]** Header title is not a filter affordance. Web makes the «Клиенты» title tappable to open the filter panel (PageHeader onTitleClick, page.tsx line 718). Mobile's title is static Text; the only entry to filters is the summary bar.

_Notes: Verified as PARITY / not gaps: filter panel (sort/status/team-city-tag facets with contextual counts, period presets+custom, reset, live «Показать N») is a 1:1 port; summary filter bar (idle «Всего N» + active tokens + «Найдено»/«Сбросить») matches; bulk delete/SMS with linked-appointment detach matches; search matcher is shared (client-search.ts, incl. address + Cyrillic/Greek translit). Explicitly NOT flagged per audit rules: header «+» create (web-parity, not a FAB); light-only theme. Two intentional mobile differences that are advantages, not gaps: (1) bulk bar adds CSV Export (web only exports from the settings screen); (2) every inbound navigation (chats, global search, unclosed, finances) pushes /clients/[id] directly, so the web ?id= deep-link intermediary — and its «Клиенты» inline-panel branches in web page.tsx — are correctly absent on mobile. The web page's inline selectedClient/draft ClientPanel branches (page.tsx lines 499-703) are also correctly replaced on mobile by dedicated [id].tsx and new.tsx routes. Filter/sort state on mobile is local useState (resets on tab remount) vs web's ?sort= URL persistence — minor and arguably fine for a tab-based app; did not raise as a gap. The quota-gating item is tagged bug because an over-cap create currently fails ungracefully rather than being pre-empted._

### client-card — PARTIAL
The client detail card ([id].tsx, LOCKED «Карта-диспетчер») is a faithful, near-complete port of the web ClientCardPage. Composer order, ClientHeader, ClientNextJob hero, CardActions, ServiceBlock spine, ObjectsBlock, and the Contacts/Personal/Meta/Attachments reference blocks all match web behavior (and several are RICHER on mobile: inline A/C-unit editing + «Записать сюда» in ObjectsBlock, debt-SMS shortcut in «Напомнить», an error+retry state in Attachments, a blacklist toggle in Meta). Pre-aimed booking deep-links (client/location/team) work end-to-end via the dashboard ?new= handler, so the memory's «?new= handler fix» concern is resolved. Remaining gaps are all inside the reference blocks plus one missing card-level action (delete). The block-order/settings «Что показывать» divergence is NOT a gap: web loadBlockConfig() is a hardcoded v1 stub and the card-fields toggles drive the LIST item, not the detail card.

- **[feature/S]** No «Удалить клиента» action on the detail card. Web ClientCardPage's ⋯ menu has delete (confirm dialog → deleteClient → onBack); mobile [id].tsx menu offers only SMS/Share/Blacklist. Deleting a single client from its own card is impossible on mobile — you must leave the card, enter list bulk-select mode, and delete there. The wrapper (deleteClientCached) already exists (used by useDeleteClients), so it only needs a menu item + Alert.confirm + router.back().
- **[polish/M]** VisitsBlock shows a de-duped service COUNT («3 услуги») instead of service NAMES («Чистка +2») like web. The web block resolves names from a `services` catalog prop; the mobile composer never wires the services catalog into the card, so visitSummary() falls back to count-or-comment. Dispatcher can't tell what was done on a past visit at a glance.
- **[feature/M]** VisitsBlock «Повторить» one-tap repeat is dropped. Web renders a ↻ button on completed visits that opens a pre-seeded new booking (client + original service ids). Mobile has no repeat affordance; re-booking a recurring job is manual. (The booking deep-link would also need to carry the `services` param, which useBookingNav currently omits.)
- **[feature/M]** FinanceBlock loyalty-tier pill is dropped. Web reads loadLoyalty()+tierForVisits() and shows the reached tier with its «−N%» discount (a gold pill), refreshing on the babun:loyalty-changed event. Mobile has no loyalty settings query, so the tier row is absent — the dispatcher loses the at-a-glance discount cue when quoting.
- **[feature/M]** FinanceBlock «Подробнее» → /dashboard/finances?client_id=X link is dropped. Web lets the operator jump from the client card to the full per-client finance ledger; mobile finances screen accepts no client filter, so the deep-dive path from the card is missing.
- **[polish/M]** NotesBlock renders note text as raw plain text. Web pipes it through <MarkdownLite>: **bold**, *italic*, «- » lists, and — notably — ::red::АЛЛЕРГИЯ:: red-highlight. On mobile a note like «::red::аллергия на хлор::» shows the literal markup, so a safety-critical highlight is lost and every note looks identical in weight.
- **[feature/M]** AttachmentsBlock can only upload images. Web uses <input type=file multiple> (accepts PDFs, scans, contracts, «скан паспорта»); mobile uses ImagePicker.launchImageLibraryAsync({mediaTypes:['images']}), so non-image documents — a stated use case in the block's own hint copy («договоры, скан паспорта») — cannot be attached from the card.
- **[polish/S]** PersonalBlock birthday uses a free-text «ГГГГ-ММ-ДД» input instead of web's native <input type=date> picker. Manual date entry is error-prone and no validation guards a malformed value that feeds the birthday-badge selector. The @react-native-community/datetimepicker dep is already used by ObjectsBlock, so a picker is low-cost to add.

_Notes: Web source of truth: apps/web/src/components/clients/ClientCardPage.tsx + blocks/*. The legacy ClientProfileView / ClientPanel are the /chats side-panel path (out of scope) — the canonical detail card is ClientCardPage, fully ported.

Two minor deltas I did NOT rank as standalone gaps: (1) the detail ⋯ menu's «Написать SMS» opens a plain sms: link whereas web «Отправить сообщение» opens SendMessagePopup (multi-channel picker) — but multi-channel comms live in CardActions on mobile, so this is cosmetic; (2) web menu has «Перейти в чат», absent from the mobile detail menu but functionally covered by the always-visible «Чат» quick action in CardActions (which even routes to the linked chat directly). If exact menu parity is wanted, add both a chat row and (more importantly) the delete row.

Verified NON-gaps per audit rules: block ordering is NOT configurable on web (loadBlockConfig() returns a hardcoded DEFAULT_BLOCK_ORDER; the settings UI is an explicit future TODO), so mobile hardcoding the same order is parity. The «Что показывать»/card-fields settings screen is at parity and drives the clients LIST item card, not this detail card. Collapse/open persistence is correctly mirrored (MMKV babun-block-open:{kind} mirrors web localStorage). No FAB/dark-mode/offline items flagged.

The delete gap is the only one that removes a capability at the card level; the rest are shallower-than-web reference blocks. Suggested priority: delete action (S) and birthday picker (S) first, then FinanceBlock loyalty+«Подробнее», VisitsBlock names+«Повторить», Notes markdown, and file (non-image) attachments._

### client-create-import — PARTIAL
Mobile client-create and CSV-import are both fully wired and largely at parity. The create screen's radical simplification (phone-primary, one card, «add rest on the card») is the LOCKED «add-client» design, not a gap — I verified the client card (ContactsBlock/PersonalBlock/MetaBlock/ObjectsBlock) does support adding every field the web create form folds into «Ещё» (messengers, source, city, birthday, email, tags/VIP, blacklist, objects), and the inline E.164 dedup guard (findClientByPhoneE164, debounced + seq-guarded) matches web. The import wizard is a faithful Upload→Mapping→Preview→Result port with the same validate/select logic, plus a superset mapping (adds `city`, richer auto-map) and stronger resume/retry. Remaining deltas: create screen has no country selector (web CountryPhoneInput does), and the importer drops three web behaviors — the `overwrite` duplicate action, the Windows-1251 encoding fallback, and the upload guardrails (10MB / 5000-row / empty / extension checks).

- **[bug/M]** Create screen has no country selector. Web /clients/new uses CountryPhoneInput with a flag picker and passes the chosen country into tryToE164(trimmedPhone, country) (clients-99 F2.7 explicitly killed the hardcoded +357). Mobile app/(dashboard)/clients/new.tsx uses a plain phone-pad TextInput and calls tryToE164(phone.trim()) which defaults to CY. For any non-Cyprus tenant entering a local-format number (e.g. a Russian '8...' or a GR local number without '+'), the E.164 the mobile create screen computes — and therefore the dedup key AND the stored phone_e164 — silently normalize under the wrong country, diverging from what web would produce. Babun is sold as multi-country SaaS, so this is a real behavior gap for non-CY tenants, not just cosmetics.
- **[feature/M]** Import wizard is missing the `overwrite` duplicate action. Web csv-validate.ts DuplicateAction is 'skip'|'overwrite'|'import_as_dup' and PreviewStep.tsx offers three radios incl. «Перезаписать существующих», with csv-import.ts implementing UPDATE-by-phone (full_name/email/comment/address) for matched rows. Mobile csv-validate.ts DuplicateAction is only 'skip'|'import_as_dup' and the PreviewStep SegmentedControl offers just «Пропустить»/«Импортировать». A user re-importing a corrected/enriched client list to update existing records has no path on mobile — they can only skip or create duplicates.
- **[feature/L]** Import drops the Windows-1251 encoding fallback. Web csv-parse.ts decodes UTF-8, detects cyrillic mojibake, and re-decodes the raw bytes as windows-1251 (explicitly for Bumpix/1C exports) and surfaces the detected encoding. Mobile csv-parse.ts reads DocumentPicker asset via fetch().text() as UTF-8 only (documented Hermes limitation) with no cp1251 path. A dispatcher importing a legacy 1C/Bumpix cp1251 CSV — a common real-world case in the RU market — gets mojibake names/cities on mobile with no recovery, whereas web imports them correctly.
- **[bug/S]** Import upload has no size/row guardrails. Web UploadStep.tsx enforces MAX_BYTES=10MB, MAX_ROWS=5000, empty-file and .csv/.txt extension checks, each with a specific RU error message before parsing. Mobile ImportWizardSheet.pick() parses whatever the DocumentPicker returns with no cap, and useImportRows chunks all rows at CHUNK=10 sequential round-trips. The upload copy claims «До 5000 строк за раз» but nothing enforces it: a 20k-row file loads fully into memory (character-scan parser) and fires ~2000 sequential insert batches — slow, memory-heavy, and un-cancellable — instead of being rejected up front like web.
- **[polish/S]** Import has no pre-flight tenant quota gate. ### auth-onboarding — PARTIAL
Mobile auth-onboarding is a close 1:1 port of web: login, register (with «check email» hub that even improves on web via resend-cooldown + open-mail), forgot-password, reset-password, and the 3-step onboarding wizard (business name → vertical → done + team checklist) all match web behavior and copy. Route guards are correctly refactored into group layouts with fail-open «unknown» semantics matching the web tenant/onboarded gate. Social OAuth is a «coming soon» stub on both sides (behaviorally equivalent — non-functional now). Three real deltas remain: reset-password dropped the confirm-password field, login is missing web's contextual error banners, and the signup email-confirmation deep link has no in-app handler.

- **[polish/S]** Reset-password screen dropped the second «Повтори пароль» confirm field. Web ResetPasswordForm.tsx has two password inputs and validates `password !== confirm` → «Пароли не совпадают» before submitting, protecting against a typo that would lock the user out of their new password. Mobile app/(auth)/reset-password.tsx has a single password input with no confirmation and no mismatch check.
- **[feature/M]** Mobile login screen has no contextual error-banner surface. Web LoginForm.tsx renders three banners driven by query params that mobile never shows: (1) `deleted` → «Аккаунт удалён. Все данные стёрты.» after account deletion; (2) `tenant_missing` → «Аккаунт настроен неправильно» with a support@babun.app mailto for the broken session-without-tenant state; (3) `link_expired`/`link_invalid` → «Ссылка истекла…» nudging the user to «Забыли пароль?». On mobile app/(auth)/login.tsx these states produce no message (grep confirms none of these strings exist in the mobile auth folder). Note: the expired-link case is partially covered elsewhere — reset-password.tsx shows its own «Ссылка истекла» card — but the deleted-account and misconfigured-tenant banners have no mobile equivalent.
- **[bug/M]** Signup email-confirmation deep link has no in-app handler. Web routes the confirmation link through /auth/callback (route.ts) which calls verifyOtp({type}) to establish a session and drop the user straight into the app. On mobile the supabase client sets `detectSessionInUrl:false` and the ONLY deep-link parser is reset-password.tsx (recovery tokens only) — a `type=signup` confirmation link opened on the device is not caught by any screen, so the user cannot be auto-signed-in from the link and must return to /login and re-enter their password. The register «Проверьте почту» hub does instruct exactly that, so it degrades gracefully, but it is a parity gap vs web's tap-link-and-you're-in flow. (Mitigated in practice if Supabase «Confirm email» stays OFF, per web UnconfirmedEmailBanner note A3.)
