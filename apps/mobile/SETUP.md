# Babun Mobile — build & stack notes

Keys, `.env.local`, Supabase and Vercel setup live in **[`docs/SETUP.md`](../../docs/SETUP.md)** —
don't duplicate them here. This file holds the native/bundler configuration that
is easy to "clean up" and expensive to get back: every item below is a bug that
already happened once.

## Prerequisites

- **Bun** — the only package manager and script runner in this repo (`bun.lock`
  at the root). There is no npm lockfile and no `node`-only script.
- **Xcode + an iOS Simulator runtime** (`xcodebuild -downloadPlatform iOS`) for
  `bun run ios`.
- **watchman** and **cocoapods** for native builds (`brew install watchman cocoapods`).
- Keep the checkout in a directory **without spaces** in its path — Expo and
  CocoaPods build scripts break on them.

## Run

```bash
bun install                 # from the repo root — workspaces apps/*, packages/*
bun run ios                 # expo prebuild (development variant) + expo run:ios
bun run android
bun run web                 # React Native Web on http://localhost:8081
```

`apps/mobile/package.json` already wraps `expo prebuild` with
`LANG=en_US.UTF-8` — CocoaPods throws `ASCII-8BIT` without a UTF-8 locale, so
don't strip it from those scripts. MMKV and SecureStore are native modules:
use the dev build (`bun run ios`), **not** Expo Go.

`ios/` and `android/` are generated by `expo prebuild` and are not in git.

After editing `babel.config.js` / `global.css` / `metro.config.js`, clear the
Metro cache:

```bash
lsof -ti tcp:8081 | xargs kill -9
rm -rf "$TMPDIR"/metro-cache apps/mobile/.expo node_modules/.cache
```

## Stack invariants — DON'T regress these

1. **NativeWind v5 (`5.0.0-preview.4`) + Tailwind v4.** NativeWind v4 does not
   support Tailwind v4 ("only supports v3"). Downgrading either half breaks
   every `className` in the app.
2. **`babel.config.js`** = preset `babel-preset-expo`, plugin
   `react-native-reanimated/plugin` (must stay LAST), and `nativewind/babel`
   applied through `overrides.exclude: /node_modules/`. Two traps: there is no
   `jsxImportSource` (that was the v4 way; v5 is a babel plugin and ships no
   jsx-runtime), and the `exclude` is load-bearing — NativeWind's import plugin
   rewrites `from "react-native-web"` inside node_modules too, which closes a
   require cycle through the react-native-web barrel and kills the **web** build
   at boot with a blank page. The reasoning is spelled out in the file's header
   comment; read it before touching it.
3. **`postcss.config.js` (`@tailwindcss/postcss`) is REQUIRED.** NativeWind v5's
   Metro transformer runs the Expo web-CSS/PostCSS pipeline over `global.css`
   first; without it `@import` / `@theme` reach lightningcss raw and fail to
   parse.
4. **lightningcss pinned to `1.30.1`** via the root `package.json` →
   `"overrides"`. `react-native-css` 3.x was built against ^1.30.1; 1.32 changed
   the visitor `Specifier` struct → "failed to deserialize" on every CSS compile.
5. **`metro.config.js` react dedup is REQUIRED — don't delete it.** The tree
   really does hold several copies of react, so the bundle must be forced onto
   exactly one. Check for yourself:

   ```bash
   # from the repo root — prints every physical copy and its version
   for d in $(find . -type d -path '*node_modules/react'); do
     echo "$d $(grep -m1 version "$d/package.json")"
   done
   ```

   Two reasons the copies keep appearing: the app pins react `19.1.0` exactly
   (RN 0.81.5's bundled renderer requires it), so bun may keep a workspace-local
   copy under `apps/mobile/node_modules/` alongside the hoisted root one; and
   libraries whose peer range predates React 19 — `lucide-react-native` declares
   `"^16.5.1 || ^17.0.0 || ^18.0.0"` — get their own nested install. Two module
   instances mean two React registries: "Invalid hook call", or the nastier
   "react and react-native-renderer must be the exact same version".

   The dedup **resolves** the path, it does not spell it out. An earlier version
   hardcoded `projectRoot/node_modules/react`; when hoisting moved and that
   directory stopped existing, every bundle — web and native alike — failed to
   resolve `react/jsx-runtime`. `require.resolve` answers the same question
   correctly whichever way bun lays the tree out, so keep it that way:

   ```bash
   cd apps/mobile && node -e 'const p=require("path");for(const n of ["react","react-dom"])console.log(n,p.dirname(require.resolve(n+"/package.json",{paths:[process.cwd()]})))'
   ```
6. **`global.css`** = the four canonical v5 imports + `@source "./app"` /
   `@source "./src"` + the `@theme` block that defines the «Halo Cobalt» tokens.
   Colours come from there and from `src/theme/colors.ts` only — see
   [`docs/DESIGN-SYSTEM.md`](docs/DESIGN-SYSTEM.md).
7. **`className` works on core RN components** (View / Text / TextInput /
   Pressable), not on wrappers like `KeyboardAvoidingView`. Screens go through
   the `Screen` primitive (`src/components/ui/Screen.tsx`) instead of styling a
   `SafeAreaView` by hand.
8. **Sentry is a no-op seam.** `src/lib/sentry.ts` exports `initSentry()`, called
   once from `src/bootstrap.ts`; the native `@sentry/react-native` module is not
   installed. Wiring it up means changing that one file — see
   [`docs/observability.md`](../../docs/observability.md).

```bash
bun test
bun run lint
bun run build:web    # exactly what Vercel runs
```
