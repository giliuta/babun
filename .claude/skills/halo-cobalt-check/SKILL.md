# Halo Cobalt — проверка соответствия

Канон: `apps/mobile/docs/DESIGN-SYSTEM.md` (путь от корня репозитория).
Токены: `apps/mobile/global.css` (@theme) и `apps/mobile/src/theme/colors.ts` —
там же и РАДИУС (`const RADIUS`, ~строка 87, наружу как `t.radius`).
В `apps/mobile/src/components/ui/tokens.ts` радиуса НЕТ: там только размеры
значков `ICON`, поле страницы `GUTTER = 16` и якорь типографики `TYPE.display`.
ВСЕГДА читай канон перед проверкой — он источник истины, не этот файл.

## Ключевые правила (сверяй с каноном)

- Кобальт `#2c5be0` (+ градиент) — единственный акцент; цвет ТОЛЬКО для смысла (статусы, деньги: доход зелёный / расход красный).
- Холодный фон `#f4f6f9`; faux-glass без expo-blur; никаких лишних градиентов и теней.
- Сдержанность Apple-Settings: «неналяписто», только ежедневно-полезные элементы, без vanity-метрик и дублей.
- Консистентность сиблингов: меняешь один фильтр/карточку/чип — приведи ВСЕ соседние к тому же стилю (правило пользователя).
- Один радиус: только `rounded-[10px]`, `rounded-t-[10px]`, `rounded-full`
  (`t.radius.card === t.radius.input === 10`). Литералы `rounded-xl/2xl/3xl` и
  произвольные числа — нарушение.
- Всплывающая панель одна — `BottomSheet`. Самописный `Modal animationType="slide"` запрещён.
- Приложение light-only: `app.json` и `src/bootstrap.ts` прибивают светлую тему,
  тёмной палитры не существует. Появление `useColorScheme` или второй палитры —
  НАРУШЕНИЕ, а не недостающая фича.

## Процедура проверки

1. Прочитай DESIGN-SYSTEM.md и файлы токенов.
2. Grep по диффу/экрану на захардкоженные цвета в обход токенов:
   ```bash
   grep -rnE '#[0-9a-fA-F]{3,8}|rgba?\(' <файлы> | grep -v -E 'theme/|global.css|tokens'
   ```
3. Grep на инлайн `style={{...}}` там, где есть NativeWind-класс или токен.
4. Grep на чужие радиусы:
   ```bash
   grep -rnE 'rounded-(xl|2xl|3xl|md|lg)' <файлы>
   grep -rnE 'borderRadius: *(7|8|9|1[1-9]|2[0-9])([^0-9]|$)' <файлы>
   ```
   Хвост `([^0-9]|$)` обязателен: без него шаблон ловит законный
   `borderRadius: 999` (радиус `pill`) и даёт десятки ложных срабатываний.
5. Сверь отступы/типографику с соседними экранами того же уровня.
6. Живая проверка на симуляторе (скил babun-sim): скриншот экрана рядом с
   соседними состояниями — «скомпилировалось» не доказательство.

## Вердикт

Отчёт: список нарушений с file:line + предложение (какой токен/класс использовать). Нарушение = ошибка, а не «вкусовщина», только если противоречит DESIGN-SYSTEM.md или правилу консистентности сиблингов.
