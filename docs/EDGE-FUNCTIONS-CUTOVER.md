серверную логику — но не в Edge Functions, а в **Postgres-функции (RPC)**. Это лучше:
атомарно, под RLS, без отдельного деплоя.

Итого реально портировать нужно было **три** функции, а не четырнадцать.

## 1. Что портировано (в репозитории, не задеплоено)

`babun-crm/apps/web/supabase/functions/`

- **`stripe-webhook/`** — приём вебхуков Stripe. Порядок «сначала аудит, потом
  сверка», идемпотентность на UNIQUE `billing_events.stripe_event_id`, разбор
  подписок и начисление SMS-пакетов через RPC `bump_sms_balance` — всё как было.
  *Главная правка под Deno:* `constructEvent` → **`constructEventAsync`**. Web Crypto
  асинхронный, синхронный вариант падает в рантайме — классическая ловушка Stripe
  на edge. Плюс `Stripe.createFetchHttpClient()` вместо нодового http-клиента.
- **`twilio-status/`** — приём статусов доставки SMS. Порядок проверок сохранён
  ровно, включая фикс STORY-078 (подпись проверяется ДО поиска строки, и неизвестный
  SID без валидной подписи получает 403, а не «ignored» — иначе ответ работал бы
  оракулом для перебора SID). `node:crypto` → Web Crypto HMAC-SHA1 + ручное
  сравнение за постоянное время.
- **`calendar-ics/`** — .ics лента для Apple/Google Calendar. `@babun/shared` в Edge
  Functions не импортируется (Deno, нет workspace-резолвинга), поэтому запрос
  встроен; заодно окно дат фильтруется в SQL, а не в JS после выгрузки всех записей
  тенанта.

**Проверено локально (без деплоя):**
- Подпись Twilio: новая реализация на Web Crypto даёт **байт-в-байт те же** подписи,
  что старая на `node:crypto` — на 5 наборах, включая кириллицу, `;`, `,`, `\`,
  пустые параметры; сравнение за постоянное время совпадает на всех ветках.
- Экранирование .ics в новой функции **символ в символ** совпадает со старым.

**Не проверено:** ни одна функция не запускалась — Deno и Supabase CLI на машине нет.
Нужен деплой в staging и живой прогон.

## 2. Что должен сделать владелец (без этого не заработает)

### 2.1 Секреты Edge Functions
```
STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET, STRIPE_PRICE_PRO, STRIPE_PRICE_BUSINESS
TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN
```
`SUPABASE_URL` и сервисный ключ платформа подставляет сама.

### 2.2 Stripe — по шагам, порядок важен
1. В Stripe Dashboard **добавить новый** endpoint на URL функции `stripe-webhook`
   с тем же набором событий, что у нынешнего.
2. Скопировать **новый** signing secret в секрет `STRIPE_WEBHOOK_SECRET`.
   ⚠️ У каждого endpoint-а Stripe **свой** секрет — текущее значение здесь не подойдёт.
3. Убедиться, что в Stripe по новому endpoint-у идут успешные доставки.
4. Только после этого выключить старый endpoint на babun.app.

**Параллельная работа безопасна:** идемпотентность держится на UNIQUE
`billing_events.stripe_event_id` — кто обработал событие первым, тот и обработал,
второй тихо выходит по 23505.

### 2.3 Twilio
1. Переключить StatusCallback URL (в Messaging Service или в параметрах отправки)
   на функцию `twilio-status`.
2. **Старый роут на babun.app оставить живым**, пока не «отстреляются» сообщения,
   отправленные со старым URL: Twilio подписывает HMAC **по вызванному URL**, поэтому
   их подписи на новом адресе не сойдутся, а ретраи идут до суток.

Параллельная работа безопасна: UPDATE идемпотентен.

### 2.4 Календарная лента
Подписки уже живут по адресу `https://babun.app/api/calendar/<id>.ics` — в Apple/Google
у пользователей. Просто удалить роут нельзя: лента молча перестанет обновляться,
ошибки никто не увидит. Нужен **301 со старого URL** на функцию (или старый роут
живёт, пока все не пересядут).

## 3. `/auth/callback` — это не Edge Function

Это браузерный редирект, который меняет ссылку из письма на сессию и ставит куку.
В мире «Expo-приложение + SPA» правильное место — **экран в самом приложении**:
`app/auth/callback.tsx` читает `token_hash`/`code` и зовёт
`supabase.auth.verifyOtp()` / `exchangeCodeForSession()` на клиенте.

Требует от владельца: обновить **Redirect URLs** в Supabase Auth.
Связано с пунктом из хендоффа про Universal Links (сейчас recovery-ссылки ходят
через `babun://` с токенами, что перехватываемо).

Экран пока НЕ написан — это следующий шаг, вместе с публичными страницами.

## 4. Структурный долг

`supabase/` сейчас лежит **внутри `apps/web`**, которую мы собираемся удалить.
Перед удалением: `git mv babun-crm/apps/web/supabase babun-crm/supabase`
отдельным механическим коммитом. Сейчас не трогал, чтобы не ломать существующий
деплой-путь и единственный `config.toml`.

## 5. Гейт удаления `apps/web` — по-прежнему закрыт

Не хватает: этих трёх функций **в проде и проверенных**, экрана `auth/callback`,
админки, публичных страниц и `/privacy` + `/terms` (на них ссылается экран
регистрации мобильного приложения — требование App Store).
