# Личное и Компании — план (2026-10-11)

Владелец утвердил модель 11.10 по макету
https://claude.ai/artifact/CMR5wgmAjEeE5uP5nuRQtv. Делаем в нашем стиле, из
нашего канона: макет показывает устройство, а не вид.

## Модель

- **Личное** — у человека: один календарь «Личный», свои события и клиенты.
  Тариф Личного: без тарифа или Соло. Партнёров в Личном нет.
- **Компания** — отдельный аккаунт: календари, участники, клиенты, услуги,
  деньги, SMS, реквизиты. Тариф компании: Про или Макс. Живёт без основателя:
  владение передаётся.
- Новый календарь заводится только в компании: Кабинет → компания →
  «Календари» → «Добавить» в шапке. В Личном и в шестерёнке календаря
  «Добавить» нет.
- Лента: «Личный │ календари компании │ календари другой компании», без
  подписей, группы разделяет тонкая черта.
- Кабинет: переключатель «Личное │ компании» и «Создать» справа.
- Роли: Владелец · Директор · Партнёр (Директор — второй этап).

## База — что уже есть

Сейчас у каждого человека ровно один свой аккаунт (`tenants` +
`tenant_members.role = 'owner'`), в чужих он `master`. Лента уже собирает
календари всех аккаунтов (`list_my_calendars`), переключение аккаунта стоит
ноль поездок (заголовок `x-babun-tenant`). Лимиты тарифов совпадают с новой
моделью: Соло — 1 календарь и 0 партнёров, Про — 5, Макс — 50.

Значит, **Личное и компания — это один и тот же `tenants`, разный `kind`**.

## Этап 1 — база (одна миграция, проверка «прогоном с откатом»)

1. `tenants.kind text not null default 'company'` (`personal` | `company`),
   `tenants.personal_of uuid unique` (чьё это Личное),
   `tenants.created_by uuid`; проверка `kind = 'personal'` ⇔ `personal_of`
   задан.
2. Разметка живых аккаунтов:
   - есть другие участники или живых календарей больше одного → `company`;
   - иначе → `personal` своего владельца (первый такой у человека);
   - каждому человеку без Личного — новое Личное: аккаунт с его именем,
     владелец, `calendar_settings`, календарь «Личный».
   - Активный аккаунт в claim'ах не трогаем: телефон остаётся там, где был
     (в том числе демо-аккаунт App Review).
3. Сторожа:
   - в Личном не больше одного живого календаря;
   - в Личное нельзя пригласить и нельзя вступить.
4. `handle_new_user`: и обычная регистрация, и регистрация по приглашению
   заводят Личное (`kind = 'personal'`, «Личный»).
5. `create_company(p_name)` → новый аккаунт `company`, человек — владелец,
   первый календарь с именем компании, пробные 14 дней Про, если человек ещё
   не брал пробный для компании.
6. `transfer_company_ownership(p_tenant, p_user)`: владелец передаёт
   участнику; сам остаётся партнёром.
7. `leave_company(p_tenant)`: партнёр выходит из компании целиком. Владелец не
   выходит — сначала передаёт.
8. `start_trial`: Личное — только Соло, компания — Про или Макс.
9. `list_my_accounts()`: мои аккаунты — id, имя, `kind`, роль, дата. `tenants`
   читает только владелец, а переключателю нужны и чужие компании.
10. Удаление аккаунта: отказ, пока человек владеет компанией, где есть другие
    участники («сначала передайте владение»).

## Этап 2 — приложение

1. Лента: Личный первым, затем компании по имени; между группами — черта
   (`ScopeChips`: разделитель между группами).
2. Кабинет: переключатель «Личное │ компании» (`ScopeChips`) и «Создать»
   справа текстом. Под ним блок выбранного аккаунта из готовых строк
   (`OwnAccountSection`/`InvitedAccounts` по `tenantId`):
   - Личное: Тариф, Реквизиты, SMS, История, Выгрузка;
   - своя компания: Календари, Партнёры, Тариф, Оплаты, Реквизиты, История,
     SMS, Выгрузка, Архив;
   - чужая: как сейчас блок пригласившего, плюс «Покинуть компанию».
3. «Создать компанию» — нижний лист: название и «Создать». После создания
   телефон переходит в компанию.
4. «Календари» компании — страница: список и «Добавить» в шапке
   (`CalendarCreateSheet`). Из шестерёнки календаря «Добавить» уходит.
5. Главный экран сам заводит «Личный» только в Личном.
6. Тариф: в Личном карточка Соло, в компании — Про и Макс.
7. «Передать владение» на странице партнёра (владелец компании).
8. Регистрация — только имя (проверить, что спрашивает сейчас).

## Доставка

Этапы 1–2 меняют тарифную страницу и создают пробный период при создании
компании — это касается тарифов, а их владелец проводит через проверку Apple.
Остальное — по воздуху. Перед отправкой — спросить владельца, как делить.
