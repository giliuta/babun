## Что требуется от владельца — осталось два шага

**1. Ключ App Store Connect API** — то, что делает отправку по-настоящему
автоматической. Без него и `eas build`, и `eas submit` требуют живого
входа в Apple, и никакой workflow не поможет.

App Store Connect → **Пользователи и доступ → Интеграции → App Store
Connect API** → создать ключ с ролью **App Manager** → скачать файл
`.p8` (даётся ровно один раз, второй скачки не будет). Оттуда же
выписать **Key ID** и **Issuer ID**.

Дальше отдать ключ в EAS:

```bash
eas credentials
```

Платформа iOS → профиль `production` → App Store Connect API Key →
указать файл, Key ID и Issuer ID. После этого ключ живёт у Expo, и
локально его хранить не нужно.

**2. Токен Expo для GitHub.** expo.dev → Account settings → Access
tokens → создать токен. Положить в репозиторий: **Settings → Secrets and
variables → Actions → New repository secret**, имя `EXPO_TOKEN`.

## Уже сделано, повторять не нужно

- `eas login`, `eas init` — проект `@artemgiliuta/babun` создан и связан.
- Счётчик сборок инициализирован единицей: `eas build:version:set`.
  Проверка — `eas build:version:get -p ios -e production`.
- Переменные окружения залиты в `production` на EAS через
  `eas env:push production --path .env.local`. **Пустые значения ломают
  команду** («Variable value can not be empty») — `EXPO_PUBLIC_SENTRY_DSN`
  в `.env.local` пуст, поэтому отправлялся отфильтрованный файл.
  Без этих переменных сборка собирается, запускается и не может войти:
  Supabase некуда стучаться.

## Как выпускать после этого

**Автоматически** — вкладка Actions в GitHub → workflow «iOS → TestFlight»
→ Run workflow. Либо тегом:

```bash
git tag v1.0.1 && git push origin v1.0.1
```

Workflow сначала гоняет `typecheck` и `bun test`, и только на зелёном
собирает и отправляет. Порядок такой намеренно: сборку, уехавшую в
TestFlight, отозвать нельзя — можно только выложить новую поверх.

Запуск **только вручную или по тегу**, не на каждый push: сборка на EAS
платная (на бесплатном тарифе — очередь), а Apple принимает ограниченное
число сборок в сутки.

**Руками, с машины** — то же самое одной командой:

```bash
cd /Users/artem/Documents/Babun/apps/mobile && eas build --platform ios --profile production --auto-submit
```

Сборка идёт 15–40 минут на серверах, терминал можно закрыть. В TestFlight
она появляется ещё через 10–40 минут — Apple обрабатывает её у себя.

## Две дороги до телефона, и когда какая

| Что изменилось | Как доезжает | Сколько ждать |
|---|---|---|
| Экраны, логика, тексты, стили — только JS | обновлением по воздуху | минута |
| Новая библиотека с нативным кодом, правка разрешений в `app.json`, смена `version` | полной сборкой через TestFlight | час-полтора |

Правило простое: если правка не требовала `bun install` нового
нативного пакета — она уедет по воздуху.

## Обновления по воздуху: две ступени

**Ступень 1 — само.** Каждый push в `master` запускает workflow
«Обновление · подготовка»: гейты, потом публикация на ветку `preview`.
На эту ветку не смотрит ни один установленный телефон — это накопитель.

**Ступень 2 — руками.** Actions → «Обновление · выкатить бригадам» →
Run workflow. Берёт последнее обновление с `preview` и переносит на
`production`, который слушают телефоны. Доходит за минуту.

Переносится ГОТОВЫЙ артефакт, не пересобирается заново: бригады
получают ровно то, что было проверено, байт в байт.

**Почему не сразу всем.** Обновление доходит за минуту — и сломанное
дойдёт так же быстро, а мастер в этот момент у клиента на объекте.
Отозвать обновление нельзя, только выпустить следующее поверх. Сорок
минут сборки раньше служили нечаянным предохранителем; ступень с паузой
заменяет его осознанно.

**Если всё-таки выкатили плохое** — не паниковать и не чинить на ходу:

```bash
eas update:rollback
```

Вернёт телефоны на предыдущее обновление.

**Ограничение `runtimeVersion`.** Политика — `appVersion`. Значит
обновления доходят только до сборок с тем же `version` в `app.json`.
Поменял версию → нужна новая сборка в TestFlight, иначе установленные
приложения перестанут получать обновления и будут молча жить на старом.

## Ошибки на телефонах: Sentry

`initSentry()` в `src/lib/sentry.ts`, вызывается из `src/bootstrap.ts`.
Без `EXPO_PUBLIC_SENTRY_DSN` — no-op, чужой чекаут не шумит в чужой
проект. В dev выключен намеренно: ошибки при живом Metro и так видны в
терминале, а квоту жгут.

Настроен узко, потому что в базе живые имена, телефоны и адреса
клиентов: `sendDefaultPii: false`, трейсинг выключен. Репортер, который
услужливо прикладывает «контекст», — это одна опечатка до того, чтобы
скопировать адресную книгу тенанта третьей стороне.

**Чего не хватает:** стек-трейсы приходят минифицированными. Чтобы
читались, нужен `SENTRY_AUTH_TOKEN` в окружении сборки плюс
config-плагин `@sentry/react-native` в `app.json`. Это отдельное
решение: плагин без токена валит сборку, поэтому сейчас его нет.

**Веб.** Переменную `EXPO_PUBLIC_SENTRY_DSN` нужно добавить в Vercel
(Project → Settings → Environment Variables), иначе веб-версия ошибки
слать не будет — EAS и Vercel про переменные друг друга не знают.

нативной части релизной конфигурации, но не проверяет подпись и приём на
стороне Apple — это видно только на настоящем `eas build`.

## Патч-дрейф Expo SDK — НЕ ЧИНИТЬ

`bunx expo-doctor` даёт 17/18 и одно предупреждение: `expo` 54.0.36 против
ожидаемых ~54.0.37, плюс `expo-constants` и `expo-file-system` на патч
позади. Очевидное лечение — `bunx expo install --fix` — **ломает веб**.

Проверено 2026-08-26 прямым опытом, а не рассуждением:

- после `expo install --fix` `bun run build:web` падает с
  `Unable to resolve module react-native-web/dist/index` из
  `expo-router/build/renderRootComponent.js`;
- на закоммиченном состоянии та же команда проходит: «Exported: dist»;
- то есть починка одного предупреждения роняет production-сборку
  babun.app — цена несоразмерна трём патч-версиям.

Побочно всплыло и то, что бамп `expo-constants` до 18.0.14 создаёт
дубль нативного модуля: `expo-asset`, `expo-linking` и
`expo-notifications` держат 18.0.13. Лечится `overrides`, но лечить
нечего — без бампа дубля нет вовсе.

Вернуться к этому стоит на следующем минорном обновлении SDK, когда
`expo-router` и `react-native-web` поедут вместе.
