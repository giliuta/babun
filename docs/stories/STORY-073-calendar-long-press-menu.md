# STORY-073 — Меню долгого нажатия и перенос по зелёным кубикам

**Дата:** 2026-09-06 · **Ветка:** `feat/unified-expo-web-2` · **Экран:** календарь
(`apps/mobile/app/(dashboard)/(home)/index.tsx`).

## Слово владельца

«Долгое нажатие на запись открывает перенести запись: нажимаю перенести — и
кубики появляются зелёные, куда можно перевести по всей таблице. Потом
копировать: выбираю запись и могу копировать её же. Потом отменить, удалить.»
Раньше (STORY-072): «карточка "Отменить визит / Удалить запись" на странице не
нужна — при долгом нажатии снизу поднимется мини-меню».

## Что сделано

- **Меню диспетчера — четыре действия:** «Перенести», «Копировать»,
  «Отменить визит» (второй лист «Причина отмены» → `cancel_reason`, список в
  `calendar/cancel-reasons.ts`), «Удалить запись» (красным). У отменённой —
  «Восстановить» (стирает причину) и без «Перенести». События: «Перенести»
  (только автор, не «весь день»), «Копировать», «Удалить событие / серию».
- **Из меню ушли:** «Открыть заявку» (тап), «Отметить оплату», «Выполнена /
  В работе / Вернуть в план», «Напомнить…», «Позвонить», «Маршрут» — деньги и
  статус живут в блоке «Оплата» страницы записи, звонок и маршрут — в её шапке.
  **Исключение:** блок «Оплата» выключен в Кабинете → в меню остаются
  «Выполнена» / «Вернуть в план», иначе визит закрыть нечем (денег они не
  пишут). Меню мастера не менялось.
- **Режим переноса.** Плашка «Перенести: Иван · Выберите зелёное время ·
  90 мин» (общий `ModePlaque` с режимом «Записать»), зелёные кубики по всей
  сетке; из Списка и Месяца календарь переезжает в Неделю записи. Окно кубика —
  вся длительность записи, собственное время записи не занято, прошлое не
  предлагается (`free-slots.ts`: `durationMinutes`, `ignoreId`, тесты). Тап по
  кубику — запись переезжает с прежней длительностью, тост «Перенесено: сб 6
  сен, 14:00 · Отменить». Выход: крестик, смена команды, уход с экрана.
- **`RescheduleSheet` удалён** — дату и время руками меняют на странице записи
  (блок «Когда»); внутри дня остаётся драг.

## Сервер: «Восстановить» упиралось в сторож финансов

На проде `protect_paid_appointment_finance` считал ЛЮБОЙ выход из
`status = 'cancelled'` изменением возвращённой оплаты и бросал «Возвращённую
оплату нельзя изменить; создайте новую заявку» — даже у заявки без денег
(`payment_status = 'unpaid'`, предоплаты и проводок нет). Значит,
«Восстановить» не работало и раньше (прежний `cancelToggle` шёл тем же путём).
Миграция `20260906235000_restore_cancelled_unpaid_appointment.sql` сужает
заморозку до денег: refunded и отменённые с предоплатой/доплатой/проводками;
отменённая без денег возвращается в план. Тело функции сверено с продом по
md5 (без комментариев и пробелов — совпало), dry-run в откатываемой
транзакции: `status=scheduled reason=null pay=unpaid`. **Применение — по слову
владельца** (миграции только с явного разрешения).

## Решения и хвосты

- Перенос в прошлое, внахлёст и в нерабочее время кубиками не предлагается —
  для этого страница записи и драг. Перенос между командами кубиками — нет.
- Выключенный блок «Оплата» → доход на основной счёт (STORY-065 П7):
  предложение — не писать доход автоматически; закрытие без блока = «Выполнена»
  в меню, деньги вносятся в Финансах. Ждёт слова владельца.
