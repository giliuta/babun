# STORY-087 — страница сотрудника (мастера) по законам страницы клиента

Владелец 23.09: «страница мастера в календаре — полная хуетень… собери заново
полностью по законам… в одном календаре у него свои доступы, в другом — другие…
хочу приглашать своих сотрудников, чтобы они пользовались и было видно, кто что
делает… 10 из 10, тестируй сам».

## Что было (аудит 23.09)

- У одного человека ТРИ разные страницы, какая откроется — зависит от входа:
  старый хаб карточки (`masters/[id]`: аватар, «Информация», «Визиты»,
  «Статистика», тумблер архива, БЕЗ прав), карточка сотрудника с аккаунтом
  (`masters/access/[userId]`: личность, календари, права словом) и карточка
  черновика/приглашения. Из общего списка «Мастера» Dmitry (с аккаунтом!)
  открывался старым хабом — права недостижимы.
- «Информация» — форма старого вида: поля в рамках, даты текстом
  «ГГГГ-ММ-ДД», подсказка про снесённый экран «Доступы».
- Права по календарям модель ДЕРЖИТ (`calendarLevels[teamId][key]`,
  `set_member_access` с `team_id`), но экран прячет календарь в ленту чипов, а
  на карточке раздел одним словом «Разное» — не понять, где что.
- Строка права ~150pt (название, фраза, сегмент во всю ширину).
- Удаление сотрудника называет число будущих записей, но передать их некому.
- Живые блоки (сервер держит): по календарю — `record.status/client/object/
  services/amount/payment/files`, `finance.operations/accounts/debts`; по
  компании — `clients`, `clients.scope`, `clients.contacts`. Остальные 37 не
  показываем (STORY-083).

## Решения

1. ОДНА ДВЕРЬ: любой вход в мастера ведёт на одну страницу человека. Карточка
   с аккаунтом → страница сотрудника; старый хаб для неё больше не рисуется.
   Карточка без аккаунта — та же страница, с дверью «Пригласить в CRM»
   (`create_invitation(p_master_id)`).
2. Блоки сверху вниз (у каждого шапка, двери — `ChooseRow compact`):
   - СОТРУДНИК — имя (плитка цвета), почта входа, телефон со «Связаться»,
     должность.
   - КАЛЕНДАРИ — строка на календарь: плитка цвета, имя и ПРАВА ЭТОГО
     КАЛЕНДАРЯ одной строкой («Записи · Деньги скрыты»); тап — права этого
     календаря; свайп — «Открепить»; дверь «Добавить календарь».
   - КЛИЕНТЫ — права компании на базу клиентов (одни на все календари).
   - РАБОТА — сводка месяца одной строкой → страница «Записи» (период,
     итоги, записи по дням). «Статистика» слита с ней (24.09).
   - ЛИЧНОЕ — день рождения и дата найма барабаном, банк и налоги строками.
   - ⋯ — «Посмотреть его глазами», «В архив / Вернуть», «Убрать из компании».
3. ПРАВА КАЛЕНДАРЯ — своя страница на календарь (заголовок — имя календаря),
   разделы «Записи» и «Деньги», строка компактная: название + фраза слева,
   короткий сегмент справа.
4. ПЕРЕДАЧА — НЕ НУЖНА (решено 24.09). Записи принадлежат календарю
   (`team_id`), `master_id` у работ пуст: человек уходит — работа остаётся в
   календаре. «Передать» = добавить в тот же календарь другого сотрудника.
   Вопрос «Убрать из компании?» называет число записей впереди в его
   календарях (раньше считал по `master_id` и всегда молчал).

## Проверка

Каждый шаг — тесты + симулятор владельца (iPhone 17 Pro) + сторона сотрудника
(«Посмотреть его глазами» и устройство сотрудника).

## Сделано (23–24.09)

- Одна дверь на человека; старый хаб и «Информация» снесены.
- Календари строками с правами этого календаря; «Добавить календарь» с
  вопросом «Как в …» / «Выставлю сам»; «Убрать» свайпом с «Отменить».
- Карточка без аккаунта — та же страница; «Пригласить в CRM» по карточке;
  отправленное приглашение стоит на месте кнопки («Приглашение ждёт
  ответа»), черновик по карточке не путается с «Новым мастером» и
  восстанавливается из карточки.
- «Записи» сотрудника — одна страница по его календарям (старые «Визиты» и
  «Статистика» искали по `master_id` и были пустыми).
- «Посмотреть его глазами» проверено: один календарь, клиент в записи
  скрыт, деньги клиентов скрыты.

### Осталось вне кода

- `supabase/functions/calendar-ics` отдаёт расписание с адресами любому, кто
  знает id пользователя. Функция НЕ развёрнута и приложением не зовётся;
  разворачивать только с токенами ленты (см. шапку файла).
- «Защита от утёкших паролей» Supabase Auth выключена — включается в
  панели Supabase (Auth → Password security), не миграцией.
