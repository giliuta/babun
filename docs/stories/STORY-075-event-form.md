# STORY-075 — Форма события по лестнице записи

**Дата:** 2026-09-06 · **Ветка:** `feat/unified-expo-web-2` · **Экран:** `/book?kind=event`.

## Слово владельца

«Давай полностью переделаем этот блок: первое — команда, второе — метка, третье
— время (по сути то же самое, что у записи), четвёртое — клиент, пятое — объект.
В событии клиента и объект выбирать необязательно, можно объект без клиента или
клиента без объекта. Услуги сюда не ставим. Внизу обычная большая заметка — и
всё». На уточняющие вопросы: название — **убрать** (имя события = его тип);
в блоке «Метка» — **типы событий** из Кабинета; «весь день», повтор и
напоминание — **убрать совсем**; объект без клиента — **просто адрес, не из
базы, хранится только на этом событии**.

## Что сделано

- Верх — `TeamLabelRow`, как у записи: плитка команды («Личное» = событие без
  команды) и плитка типа (значок Tag, плейсхолдер «Тип»; цвет — цвет типа).
  Оба открываются `PickerSheet`; у типов шестерёнка ведёт в Кабинет →
  «Типы событий».
- Время — `WhenRow` + тот же лист даты/времени, без «весь день».
- Клиент — необязателен: строка «Выбрать клиента», у выбранного — звонок,
  «···» (карточка) и «✕» (убрать). Клиент и объект независимы.
- Объект — адрес события: поле «Адрес или ссылка на карту» (`address`; ссылка
  уходит в `event_url`). У клиента с объектами — строка «Объект клиента»,
  которая подставляет адрес объекта (`location_id` пишется только при клиенте).
- Заметка — большое поле последним (`event_notes`).
- Сняты: название, чипы типа, «весь день», «Личное/команда»-чипы,
  «Подробности» (заметка/место/ссылка), напоминание, повтор. У прежних событий
  их значения не трогаются — уезжают как загрузились; название прежнего
  события без типа остаётся его именем, а совпадающее с типом название сам
  находит свой тип.
- Кнопка активна без названия: событие называется типом, без типа — «Событие».
