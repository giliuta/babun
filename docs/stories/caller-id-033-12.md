# Определитель номера — имя клиента на входящем звонке (идея 033 №12)

Статус: iOS сделан в ветке `claude/033-caller-id-84e245`, ждёт нативной
сборки и настроек Apple Developer. Android отложен (разбор ниже).

## Что видит человек

Клиенты → шестерёнка → группа **«Звонки»** → выключатель **«Имя клиента при
звонке»** («Для номеров не из контактов»). Включили — пока iOS не разрешил
расширение, строка говорит «Выключено в настройках iPhone», а под ней дверь
**«Включить в настройках iPhone»** · «Телефон → Блокировка и идентификация
вызовов → Babun»: тап открывает ровно эту страницу Настроек
(`CXCallDirectoryManager.openSettings`). Разрешили — «Включено на этом
iPhone», двери нет.

При звонке с номера клиента, которого нет в контактах телефона, iOS
подписывает его: **«Andreas Georgiou · Paphos · Babun»** (город — метка
клиента, если есть; без неё «Andreas Georgiou · Babun»). Дополнительный
номер карточки — «Мария · Andreas Georgiou · Babun».

## Как устроено

| Часть | Файл |
|---|---|
| Список номеров: E.164 без «+», строго по возрастанию, без повторов (иначе CallKit отвергает весь список) | `apps/mobile/src/features/clients/caller-id/caller-id-entries.ts` (+ тест) |
| Мост в Swift: запись файла в App Group, `reload`, статус, дверь в Настройки | `apps/mobile/modules/caller-id/ios/CallerIdModule.swift` |
| Само расширение (CallKit Call Directory) | `apps/mobile/modules/caller-id/extension/CallDirectoryHandler.swift` |
| Config plugin: App Group у приложения, ключи в Info.plist, цель `BabunCallDirectory` в Xcode | `apps/mobile/plugins/with-call-directory.js`, подключён в `app.config.js` |
| Синхронизация: список клиентов изменился → через секунду файл и `reload` | `caller-id/CallerIdSync.tsx` в `app/(dashboard)/_layout.tsx` |
| Выключатель и дверь | `caller-id/CallerIdSettingsGroup.tsx` в `settings-page/SettingsBody.tsx` |

- Файл — `caller-id.txt` в контейнере App Group, строка «цифры<TAB>подпись».
  Пишется только если изменился; `reload` — только после изменения.
- Каждый запрос расширения — полная перезапись базы (удалённый клиент не
  остаётся в телефоне). Номер не больше предыдущего расширение пропускает —
  испорченный файл стоит одной подписи, а не всех.
- Выключили — файл пустеет, iPhone никого не подписывает.
- В «зеркале» (его глазами) и пока список не загружен синхронизация стоит:
  иначе пустой или урезанный ответ стёр бы подписи.
- Идентификаторы: приложение `com.babun.crm` → расширение
  `com.babun.crm.CallDirectory`, группа `group.com.babun.crm`; dev-клиент —
  `com.babun.crm.dev(.CallDirectory)`, `group.com.babun.crm.dev`.

**Права (правило 10).** Своего права нет и не нужно: телефон подписывает
ровно тех клиентов и те номера, что человеку уже отдаёт сервер (RLS клиентов,
уровень «Телефоны»); скрытый номер в файл не попадает, потому что его нет в
ответе. Настройка — телефона, а не команды (`devicePrefKey`), в базу не пишет.

**Сборка без расширения** (веб, Android, старый dev-клиент соседа) модуля не
знает: `requireOptionalNativeModule` → строки «Звонки» нет вовсе, синхронизация
не запускается. Падения нет.

## Как проверено

- `bun test` списка: 9 тестов (порядок числом, повторы, страна доп. номера,
  корзина, длинное имя, разделители в имени).
- Сборка dev-клиента с расширением на Xcode 27.1: `BUILD SUCCEEDED`; в
  `PlugIns/` лежит `BabunCallDirectory.appex`, у приложения и расширения в
  подписи `group.com.babun.crm.dev`.
- Симулятор iPhone 17 (`2207393B`): `pluginkit` видит
  `com.babun.crm.dev.CallDirectory(1.0.3)` — расширение зарегистрировано.
- Приложение на локальном стенде: выключатель включён → в
  `AppGroup/…/caller-id.txt` появился список клиентов; выключен → файл 0 байт;
  клиент добавлен в базу → после обновления списка файл догнал
  (`Andreas Georgiou · Paphos · Babun` встал по порядку).
- Код расширения (без правок, CallKit заменён заглушками со строгой проверкой
  порядка) принял список 1500 клиентов стенда: 1500 строк → 1500 записей.
- **Статус `enabled` на симуляторе недостижим ни для какого приложения:**
  системная служба CallKit там зашита на `/var/mobile/Library/CallDirectory`,
  которого в симуляторе нет (`Unable to initialize CXCallDirectoryStore … 513`),
  поэтому `reload` и `getEnabledStatus` отвечают ошибкой 0. Проверяется только
  на настоящем iPhone.
- Локальная сборка на Xcode 27 падает при запуске (iOS 27 SDK требует UIScene,
  у Expo 54 его нет) — для проверки бинарник помечен SDK 26.5 через `vtool`.
  Сборки EAS идут на образе с Xcode 26 — их это не касается.

## Что ждёт владельца

1. **Apple Developer → Identifiers.** Самое простое — интерактивная сборка
   `eas build -p ios --profile production`: EAS по `appExtensions` из
   `app.config.js` сам заведёт `com.babun.crm.CallDirectory`, включит App
   Groups и создаст профили (спросит вход в Apple). Вручную:
   - App Groups → «+» → `group.com.babun.crm`;
   - App ID `com.babun.crm` → Capabilities → App Groups → отметить группу;
   - новый App ID `com.babun.crm.CallDirectory` → App Groups → та же группа.
2. **Новая нативная сборка** (по воздуху нельзя: новая цель, entitlements,
   нативный модуль) → TestFlight → App Store. В App Review: расширение
   только подписывает номера клиентов компании, ничего не блокирует.
3. Версия расширения берётся из `app.json` (`version`, `ios.buildNumber`);
   при `appVersionSource: remote` проверить в первой сборке, что номер сборки
   расширения совпал с приложением (иначе только предупреждение App Store).

## Как проверить на настоящем телефоне

1. Поставить сборку, войти, Клиенты → шестерёнка → «Имя клиента при звонке» —
   включить.
2. Тап «Включить в настройках iPhone» → откроется «Блокировка и идентификация
   вызовов» → включить **Babun** → вернуться: строка «Включено на этом iPhone».
3. Завести клиента с номером второго телефона, которого НЕТ в контактах, —
   через секунду база обновится сама.
4. Позвонить со второго телефона: на экране «Имя · Город · Babun».
   (Номер, записанный в контактах iPhone, iOS подписывает контактом — это
   правильно.)

## Android — отложено

Аналога Call Directory у Android нет: стороннее приложение не может вписать
имя в системный экран звонка.

- **CallScreeningService** (Android 10+, роль `ROLE_CALL_SCREENING`, человек
  выдаёт её одним системным диалогом). Служба получает каждый входящий с
  номера НЕ из контактов — ровно наш случай — и может лишь пропустить,
  заглушить или сбросить звонок. Имя показать можно только своим
  уведомлением поверх звонка («Andreas Georgiou · Babun»). Работа: служба на
  Kotlin + config plugin (манифест), запрос роли из той же строки
  «Звонки», список номеров в файле приложения. Около 1–2 дней и новая сборка
  Android. **Это рекомендуемый путь, когда дойдём.**
- **Оверлей поверх экрана звонка** — нужен `SYSTEM_ALERT_WINDOW` (он у нас
  намеренно в `blockedPermissions`) и чтение номера звонка
  (`READ_PHONE_STATE`/`READ_CALL_LOG` — Google Play пускает это только
  приложениям-звонилкам). Отказ.
- Запись клиентов в контакты телефона — `WRITE_CONTACTS` тоже заблокирован и
  засоряет книгу человека. Отказ.

## Хвосты

- Строку «Звонки» видит тот, кому открыта хоть одна строка шестерёнки
  клиентов; мастеру без таких прав её пока не видно.
- В базу идут клиенты активной компании; партнёр с несколькими компаниями
  получит подписи той, в которой сейчас.
- После «Выйти» список остаётся в iPhone до следующего входа (вход
  перепишет его). Если нужно — чистить файл на выходе из аккаунта.
