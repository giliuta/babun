# Полный аудит мобильного приложения Babun — 2026-07-02

Многоагентный аудит (97 агентов): 10 измерений, каждая high/medium-находка адверсариально верифицирована независимыми скептиками чтением кода (high — двумя). Ни одна находка не опровергнута.

**Итог: 70 подтверждённых находок** (16 high / 54 medium), 50 low (не верифицировались), 6 сверх лимита верификации.

## Состояние по измерениям

### calendar
Каркас календаря портирован добротно: day/week time-grid с корректной interval-graph overlap-раскладкой, drag-перенос по времени, месяц, agenda, header без «г.», dropdown режимов и командные чипы соответствуют духу веба. Однако финансовый футер показывает фейковые данные (Расход захардкожен в €0, Доход не различает planned/earned и игнорирует paid_amount), рабочие часы перепутаны с видимым окном сетки (записи вне 06:00–22:00 рисуются вне сетки или невидимы), линия «сейчас» не тикает, all-day события с веба невидимы, а таймзона бизнеса игнорируется. По паритету не хватает целого слоя: режим «3 дня», MiniCalendar, FAB, метки/города дней, расписание/перерывы/буферы, gridStep, финансы в ячейках месяца и long-press действия над записью.

Не портировано / не доделано:
- Режим «3 дня» (web: day/3days/week/month/agenda) — на мобильном отсутствует
- MiniCalendar — месячный поповер по тапу на заголовок для прыжка к дате — не портирован
- CalendarFab / кнопка «+» — на мобильном запись создаётся только тапом по пустому слоту или из пустого agenda; в непустом agenda и в month создать запись напрямую нельзя
- Метки/города дней: CityPickerModal, chip метки в шапке дня, тонировка колонки цветом метки (tint_days_by_label), цветной «spine» — не портированы
- Шапка колонки дня (web DayColumn header: число, выходные красным, счётчик, метка) — в мобильном day-режиме шапки дня нет вообще, в week — упрощённая
- Личный календарь как закреплённый таб «Мой календарь» + drag-reorder табов бригад (web v511) — на мобильном только фильтр «Все»/бригады
- Long-press меню записи (ActionMenuModal), RescheduleSheet (перенос на другую дату), RepeatCopyModal (повтор/копирование) — не портированы
- Drag записи между днями в week-режиме (web dnd-kit колонки-droppable) — мобильный drag только по вертикали внутри дня
- Расписание команды: нерабочие часы (out-of-hours wash), перерывы «Перерыв», особый график (SpecialScheduleModal) — не портированы
- bufferMinutes — штрихованные буферы после записей и запрет брони внутри буфера — не портированы
- gridStep (15/30/60): суб-часовые линии сетки и snap пустого тапа/переноса по шагу — мобильный всегда тап по :00 и snap 15 мин
- scrollOpenHour — авто-скролл сетки к рабочему часу при открытии — не реализован (ScrollView всегда с верха)
- Финансовые мини-строки в ячейках месяца (planned/earned/spent/profit, web MonthView) — мобильный месяц показывает только счётчик записей
- Валидация записи (validateApt) и цветовая логика getAppointmentColorKind (по статусу/валидации/property_type) — мобильные цвета только по статусу
- «Маршрут дня →» (Google Maps deep-link по адресам дня) в agenda — не портирован
- SyncIndicator и CalendarLegend — не портированы
- PersonalEventBlocks / EventPresetChips (пресеты личных событий) — в мобильном есть только ручное «Событие» в AppointmentSheet
- Дедупликация при создании клиента из брони (проверка телефона, «Открыть» существующего — по утверждённому add-client решению) — inline-создание в ClientPickerModal не проверяет дубли, primary-поле — имя, а не телефон

### clients
Ядро измерения «Клиенты» на мобильном портировано добротно: список с поиском и простым фильтром (Статус/Тег/Город), детальная карточка-композер с header + NEXT-JOB hero + 7 блоками на shared-селекторах, создание с телефоном-первым (autofocus + save-gate) и CSV-импорт. Главные реальные баги: посимвольные Supabase-мутации в ContactsBlock (лагающий ввод и гонки), непереданный каталог тегов в MetaBlock (теги с карточки не назначить), «Должники» по мёртвому полю balance, отсутствие phone_e164/дедупа при создании (подрывает дедуп всего продукта) и потерянный locationId в цепочке «Записать на ТО». Из утверждённых решений не портированы «Настройки клиентов» с «Что показывать», money row + meta на карточке списка, инлайн-дедупликация «Открыть», фасеты Команда/Период и весь слой quick-actions/service-spine/attachments детальной карточки.

Не портировано / не доделано:
- Фасеты «Команда» и «Период» в панели фильтров не портированы (в filter.ts:3-4 помечены deferred); нет и токен-бара с удаляемыми фильтрами (ClientsFilterBar)
- Сегменты «Статус» не совпадают с вебом: нет «Дни рождения», «Давно не были», «Новые», «Постоянные» (SEGMENT_OPTIONS в useClientFilters.ts); мобильный добавил свой «Активные»
- Сортировка (pills Недавние/Имя/Выручка/Кондиционеры) и pinned-first (pinned_at) не портированы — список всегда по алфавиту
- «Настройки клиентов» (шестерёнка) и «Что показывать на карточке» (ClientsSettingsScreen + CardFieldsScreen, cardFields-тогглы) — полностью отсутствуют на мобильном
- Money row + meta на карточке списка (утверждённый v811) не портированы — карточка показывает только имя/телефон/город/баланс
- Создание клиента ≠ «сразу карточка» (утверждённое решение «create IS the client card»): на мобильном отдельная форма из 2 полей; нет CountryPhoneInput, нет «Ещё»-свёртки, нет добавления объекта при создании
- Инлайн-дедупликация по телефону («Открыть» при совпадении) и заполнение phone_e164 — не реализованы ни в создании, ни в импорте
- ClientQuickActions (5 видимых действий) и ClientServiceSpine («ОБСЛУЖИВАНИЕ», wiring serviceDueState) на детальной карточке — не портированы
- AttachmentsBlock (фото/вложения через Supabase Storage) — не портирован (TODO в [id].tsx:12-14)
- Блоки карточки не сворачиваются и их порядок/видимость не настраиваются (веб: ClientCard + loadBlockConfig)
- Оборудование (кондиционеры) в ObjectsBlock не отображается и не редактируется — ТО-логика (serviceDue) не может быть заполнена с мобильного
- Импорт CSV: нет мастера с маппингом колонок, превью-валидацией и резюмом (web ImportWizard/csv-validate/csv-resume); импорт последовательный, без дедупа
- Экспорт CSV / GDPR-экспорт клиентов — отсутствует
- Удаление/восстановление клиента (soft-delete, selection mode, массовые действия, long-press меню, канал-пикер звонка) — отсутствуют
- FinanceBlock: лояльность (скидка-тир) и ссылка «Подробнее» в финансы — не портированы (задокументировано DEGRADED)
- VisitsBlock: названия услуг из каталога и кнопка «Повторить» — не портированы (задокументировано DEGRADED)
- ReactivationWidget и виджеты сегментов на списке — не портированы

### finances
Ядро мобильных финансов (лента finance_transactions, per-team счета с brigade_id, переводы парой строк, шаблоны, категории) портировано и корректно ходит в те же Supabase-репозитории, что и веб, но денежная математика в трёх местах расходится с источником истины: обзор и «Разбор» игнорируют возвраты, а касса close-day (несмотря на фикс af0349a2) считает cash по всем статусам дня и теряет предоплаты. Самый опасный дефект — возможность отредактировать или удалить одну ногу перевода из ленты, что ломает инвариант пары и портит балансы счетов (deleteTransfer в mobile не используется). Утверждённый дизайн v5 реализован частично: нет строки «Долги», tinted-карточек и tap-фильтров, «Счета» не вынесены в отдельную карточку; из функционала не портированы должники, аналитика, инвойсы, возвраты с привязкой и серверное сохранение закрытия дня.

Не портировано / не доделано:
- «Долги»: totals.debt и список должников (web DebtorsList + карточка «Долги» в обзоре) не портированы — на мобиле долги вообще не видны в финансах
- Аналитика (web AnalyticsSheet: сводка периода + разбор «по бригадам» через allTeamTx) отсутствует
- Инвойсы: выставление инвойса из операции (web InvoiceSheet, invoice_id) не портировано
- Возврат по операции: веб-флоу «Создать возврат» из TransactionPopup с refund_of_id и капом «до остатка» не портирован; мобильный «Возврат» — свободная операция с положительной суммой без привязки (веб пишет отрицательную с refund_of_id)
- Фото чека (receipt_url, bucket receipts) в мобильном OperationSheet не поддерживается
- Tap-фильтры обзора (Счета/Доход/Расход/Долги/Прибыль переключают контент ленты) не портированы — только сегмент «Операции/Разбор»
- «Разбор» дохода по услугам через tx.appointment_id (web breakdownIncome: категория → услуга привязанной записи → «Доход») не портирован — весь авто-доход падает в «Без категории»
- Лента операций не показывает клиента/услугу записи (web TransactionsFeed: имя клиента + переход в карточку) — income через tx.appointment_id отображается только заметкой
- Закрытие дня: снапшот пишется только в локальный MMKV (babun:closed-day:*), в Supabase не сохраняется; сущность DailyReconciliation per-brigade из docs/finance-model.md не реализована; недостача (delta < 0) никуда не проводится
- Подтверждение «Остались запланированные записи — закрыть всё равно?» при закрытии дня (web confirm) не портировано
- Скоуп финансов: веб — строго одна бригада (по умолчанию первая, без «Все»), мобайл добавил чип «Все» с дефолтом null — расходится с решением «accounts → strict per-team»
- Кастомный период v5 задуман колёсами С–До (wheels) — на мобиле compact-пикеры (календарный поповер)
- PDF-экспорт финансов (web pdf-export.ts) не портирован
- Кнопка «Настройки финансов» (шестерёнка в хедере веба → settings/finance) отсутствует в хедере мобильных финансов (категории/шаблоны спрятаны в Кабинете)

### chats-cabinet
Измерение «chats-cabinet» в рабочем состоянии для ежедневного MVP-использования: заглушек ScreenPlaceholder в проде не осталось, все 18 экранов кабинета и оба экрана чатов реальные, базовый CRUD справочников (команды/мастера/города/услуги, с edit и мягким delete) работает поверх Supabase. Главные проблемы — автопосев фейковых демо-чатов вопреки STORY-053a (и их невозможно удалить), системное отсутствие обработки ошибок во всех create/delete-мутациях кабинета и «двоевластие» хранилищ: настройки календаря/лояльности/типов событий и склад пишутся в MMKV устройства, хотя канонические таблицы Supabase уже существуют и используются вебом. По паритету мобильные справочники — тонкий срез веба (команды без цвета/состава/подразделов, мастера без профиля и прав, чаты без pin/статусов/«Без ответа»), а в аккаунте нет обязательного для App Store удаления аккаунта.

Не портировано / не доделано:
- Чаты: нет меню действий диалога — закрепить/открепить, закрыть, в архив, «Создать клиента», «Записать на приём», «Открыть карточку клиента» (весь header-⋮ веба)
- Чаты: нет фильтра «Без ответа» с SLA-бейджем и счётчиков в чипах каналов; нет галочек доставки/прочтения (✓/✓✓), группировки сообщений по датам, копирования сообщения, фото-вложений; поиск не ищет по телефону и @handle
- Чаты: не портирована кнопка «Загрузить демо-чаты» по запросу (STORY-053a); нет бейджа непрочитанных на иконке таба «Чаты»
- Команды: только CRUD имя+регион — нет детального хаба команды и 6 подразделов веба (календарь, города/метки, мастера, услуги, оборудование, appointment-blocks), нет цвета, лида/участников, payout %, архива, дублирования и ручной сортировки
- Мастера: только имя+телефон — нет профиля из 7 секций веба (аккаунт-логин, личное, работа, зарплата, права/permissions, документы, заметки), нет привязки к команде и ролей
- Услуги: нет категорий услуг с цветами, цвета услуги, bulk-цен (от N шт → цена), привязки услуг к командам
- Аккаунт: только просмотр email/даты/ID — нет смены пароля и безопасности, экспорта данных (GDPR), удаления аккаунта (требование App Store 5.1.1(v)), биллинга, персонального календаря
- Кабинет: нет SMS-шаблонов (текущие «Шаблоны» — только финансовые операции), настроек SMS-отправителя, онлайн-записи (booking_slug), интеграций (Telegram/webhooks), участников и приглашений (web settings/team)
- Не портирован экран «Незакрытые дни» (web /dashboard/unclosed) — в группе «Смена» кабинета его нет, хотя data-слой готов
- Повторяющиеся ТО: нет авто-создания напоминания из завершённой записи (основной источник на вебе), нет «Записать» (создание брони из напоминания), нет выбора даты последнего ТО и разделения «пора / будущие»
- Склад: не мигрирован на public.equipment (таблица есть с 20260624_001); нет per-team представления, поиска и выбора цвета
- Настройки Календарь/Лояльность/Типы событий: не мигрированы на таблицы Supabase (calendar_settings + repo, tenant loyalty 20260624_003, personal_event_types 20260624_002) — живут в MMKV устройства
- Настройки финансов веба (VAT-режим/ставка, web settings/finance) не представлены в кабинете

### auth-security
Фундамент auth-слоя крепкий: токены в Keychain через чанкованный SecureStore-адаптер, publishable-ключ не закоммичен (.env.local в gitignore, git-grep чистый), RLS в БД многослойная (tenant + роли + защита owner_user_id), анти-энумерация и локализация ошибок на месте, брендинг логина — Babun (SaaS), без AirFix. Главные проблемы — вокруг устройства, а не сервера: выход из аккаунта не очищает нешифрованный MMKV с чатами/финансами (кросс-тенантная утечка на общем устройстве), recovery-токены едут через перехватываемую кастомную схему babun://, а ролевая модель RLS вообще не отражена в мобильном UI. Ключевые недоделки — Google/Apple OAuth (в web готовы, в mobile заглушки), удаление аккаунта и наблюдаемость (Sentry no-op).

Не портировано / не доделано:
- Google/Apple OAuth не портированы: в web есть signInWithGoogle/signInWithApple (apps/web/src/lib/supabase/auth-client.ts:119-140), в мобильном — заглушки «подключаем в следующей сборке» (login.tsx:51-55, register.tsx:84-88); для нативного iOS нужен expo-apple-authentication + signInWithIdToken, для Google — expo-auth-session/Google Sign-In
- signUp не передаёт options.emailRedirectTo — письмо подтверждения регистрации ведёт на веб-Site URL, возврат в приложение только вручную (register.tsx:59-63); deep link сделан лишь для reset-password
- Allowlist Redirect URLs в Supabase (babun:///reset-password для прода и exp://… для dev-сборки) нигде не зафиксирован в коде/доках — если URL не в allowlist, Supabase молча подменит его на Site URL и сброс уйдёт на веб
- Ролевая модель owner/dispatcher/crew и мульти-тенантность (app_metadata.available_tenants, переключение тенанта) не портированы в мобильное приложение — mobile всегда работает с одним tenant_id
- Смена пароля и email авторизованным пользователем из кабинета отсутствует (только через forgot-password flow); экран «Аккаунт» read-only
- Sentry — no-op заглушка (src/lib/sentry.ts, Phase 8): ошибки аутентификации в проде никуда не репортятся
- Face ID заявлен в app.json (faceIDPermission для expo-secure-store), но requireAuthentication не используется — биометрического app-lock нет
- Удаление аккаунта (GDPR, App Store Guideline 5.1.1(v) — обязательное требование для приложений с регистрацией) в мобильном приложении отсутствует

### design-system
Ядро «Halo Cobalt» держится хорошо: единый runtime-источник цвета (useThemeColors) с честной light/dark-инверсией покрывает практически все экраны, семантика (кобальт=действие, зелёный/красный=деньги, тинты бейджей от токенов) соблюдается, градиент действительно живёт только на бренд-поверхностях auth. Главные системные долги — незатокенизированная заливка чипов/инпутов «#eef1f5 | rgba(255,255,255,0.07)» (48 ручных повторов), ручные карточки rounded-2xl+shadow-sm мимо Card-примитива (радиус 16 vs 20 и серая тень в дарке) и FAB без положенного градиента; из точечных багов — невидимая белая надпись «Сохранить» на светлой disabled-кнопке в ObjectsBlock и неинвертируемый +not-found. Дальше стоит извлечь токен chipFill и примитивы Chip/SegmentedControl/FAB, после чего расхождения будут закрываться одной правкой вместо десятков.

Не портировано / не доделано:
- Токен для главной заливки чипов/инпутов (#eef1f5 | rgba(255,255,255,0.07)) не заведён ни в global.css, ни в ThemeColors — 48 ручных повторов ждут экстракции
- Нет общих примитивов Chip и SegmentedControl — каждый экран (OperationSheet, AppointmentSheet, accounts, calendar-настройки, MetaBlock, PersonalBlock, finances) реализует свои
- Dark-палитра существует только в runtime (src/theme/colors.ts); global.css @theme содержит одну светлую тему, NativeWind dark:-варианты не подключены — цвет принципиально не может идти через className
- Tab bar из DS §5 («glass panel, top hairline», FAB accent-gradient) не портирован: сплошной t.surface без glass-материала (app/(dashboard)/_layout.tsx:20-23)
- Компонент Halo (src/components/ui/Halo.tsx) написан, но не используется ни на одном экране — амбиентный halo есть только на auth, хотя DS §4 предписывает «login + headers»
- Display-типографика (34/800) для заголовков рутов не применена нигде — все табы на 24/700

## Роадмап

Мобильное приложение — функциональный MVP по всем 5 табам с полностью раскатанной системой «Halo Cobalt» (+dark mode) и календарём, доведённым до web-вида по слайсам 0–4a (day/week time-grid, dropdown видов, финансовый футер); close-day и auth parity-баги закрыты. До паритета остались 3 блокера P0 (onboarding-гейт с tenant-fallback, дедуп клиентов, offline-first sync из Phase 2 — expo-sqlite установлен, но replayer не портирован, приложение online-only вопреки LOCKED-решению), затем P1-паритет: экраны Unclosed/SMS-шаблонов, хабы Teams/Masters с сабрутами, глубина финансов (Долги/возврат/инвойс), календаря (recurrence, 3 дня, блоки шита), клиентов, чатов, услуг, настроек (включая Apple-обязательный account-delete) и push+Sentry; P2 — Insights, Audit-лог, inventory и нативная полировка (blur/haptics) после ребилда.
