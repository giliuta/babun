## 4. КОЛИЧЕСТВО И ВРЕМЯ

**Механика (не меняется, меняются только слова и контролы):**
- цена за штуку = `price_tiers`, побеждает ступень с наибольшим `min_qty ≤ qty`; `min_qty ≥ 2` — инвариант рантайма;
- время: без ступени `duration_minutes × qty` (за штуку), со ступенью — `duration_minutes` ступени ЦЕЛИКОМ на строку;
- `bulk_threshold/bulk_price` продолжают писаться зеркалом первой ступени (их читает shared и легаси-веб) — не трогаем;
- `is_countable = false` выключает обе лестницы: тумблер «Продаём штуками» и есть этот бит.

**Слова на экране:**
- база: `1–2 шт — 45 € за шт · 30 мин за шт` (верхняя граница = `min_qty` первой ступени − 1; без ступеней `1 шт — 45 € · 30 мин`);
- ступень свёрнутая: `От 3 шт — 40 € за шт · всего 1 ч 20 мин`;
- ступень раскрытая, три контрола с ЖИВОЙ подстановкой N:
  - `От скольких штук` — number-pad;
  - `Цена за штуку` — `MoneyField`;
  - `Время на все 3 шт` — `TimeWheelPair` (N подставляется из текущего порога);
- эхо под контролами: `3 шт × 40 € = 120 €, 1 ч 20 мин на всё`.

**Ошибки** (валидатор `src/features/services/economics.ts` не меняется, меняется канал показа): ступень не пишется в базу, остаётся раскрытой, красная подстрока живёт в строке и **видна в закрытом виде**: «Укажите цену или время», «Такой порог уже есть», «Порог — от 2 штук».

**Удаление ступени:** свайп влево (`fullSwipe` выключен) + словесный дублёр long-press → системный `Alert` «Убрать условие «от 3 шт»?».

## 5. СКИДКИ

**Своего поля скидки у услуги не появляется** (ни процента, ни суммы, ни срока акции, ни тумблера «участвует в скидках»). Причина, которую надо сказать владельцу вслух: скидка в продукте уже есть в трёх местах, и все три на проде имеют по нулю применений, а итог правят руками в 20 записях из 30; лояльность физически пишет в `global_discount` и считает «ручной» любую заполненную скидку — четвёртое поле либо сотрёт её, либо будет ею стёрто.

**Порядок применения (фиксируется как закон):**
```
лестница по количеству (цена за штуку)
  → строка записи (qty × цена)
  → subtotal
  → global_discount  (сюда пишут И ручную скидку, И лояльность — одно поле)
  → ручной итог (customTotal)
  → НДС серверным триггером
```

**Где видно:** страница услуги отвечает на вопрос тремя строками-фактами (см. §3), сама скидка живёт в записи и в лояльности.

**Если скидка услуги когда-нибудь понадобится** (не сейчас): только в существующее `line.discount` в `src/features/appointments/helpers.ts:134-170`, между лестницей и subtotal, и ТОЛЬКО после двух починок — `totalPrice = lineTotal(line)` (сейчас `price × qty` без вычета) и сведение округления в одну функцию (сегодня корзина «12,50 + 2×10,50, −10 %» даёт 30,50 в `/book` и 31 в редакторе). Никогда — в `global_discount`, никогда — уменьшением `pricePerUnit` (`originalPrice` служит признаком ручной правки и такая скидка навсегда отключит лестницу).

**Имя строки счёта берётся из снапшота записи, а не из живого каталога:**

В том же заходе расширяются `p_lines` в `issue_invoice`, `packages/shared/src/db/repositories/invoice-write-helpers.ts` и `assertInvoiceControlRead` в `repositories/invoices.ts` — иначе каждое выставление упадёт «Контрольное чтение инвойса не совпало».

### Миграция
`apps/web/supabase/migrations/20260817150000_services_belong_to_one_team.sql` — data-only + одна колонка, по рецепту `20260815150000_accounts_belong_to_one_team.sql` (факты в шапке → backfill → NOT NULL → FK → guard → индексы → закон комментарием).

```sql
-- ФАКТУРА НА 2026-08-17 (проверено SQL по проду):
--   услуги есть у двух тенантов: Giliuta (3 / 3 активные команды), test@babun.dev (3 / 2).
--   brigade_ids: одна услуга -> ["team-mr6g20lt-bzm6j"] (команда Y&D, is_active=false),
--   две -> [] ("делают все"). price_tiers/duration_tiers/cost_per_unit пусты у всех.
--   ЗАКОН: услуга принадлежит ровно одной команде.

alter table public.services add column if not exists team_id text;
alter table public.services add column if not exists invoice_note text;

-- ШАГ 1. Владелец из ИСТОРИИ записей (где услуга реально продавалась),
--        затем первая АКТИВНАЯ команда из brigade_ids, затем первая активная по position.
with from_history as (
  select s.tenant_id, s.id as service_id, a.team_id,
         count(*) as n, max(a.starts_at) as last_at
    from public.services s
    join public.appointments a on a.tenant_id = s.tenant_id
    join lateral jsonb_array_elements(coalesce(a.services, '[]'::jsonb)) l on true
    join public.teams t on t.tenant_id = a.tenant_id and t.id = a.team_id and t.is_active
   where l->>'serviceId' = s.id and a.team_id is not null
   group by 1,2,3
),
history_pick as (
  select distinct on (tenant_id, service_id) tenant_id, service_id, team_id
    from from_history order by tenant_id, service_id, n desc, last_at desc
),
brigade_pick as (
  select distinct on (s.tenant_id, s.id) s.tenant_id, s.id as service_id, t.id as team_id
    from public.services s
    join lateral jsonb_array_elements_text(coalesce(s.brigade_ids, '[]'::jsonb)) b on true
    join public.teams t on t.tenant_id = s.tenant_id and t.id = b and t.is_active
   order by s.tenant_id, s.id, t.position, t.id
),
first_active as (
  select distinct on (tenant_id) tenant_id, id as team_id
    from public.teams where is_active order by tenant_id, position, id
)
update public.services s
   set team_id = coalesce(h.team_id, b.team_id, f.team_id)
  from first_active f
  left join history_pick h on false -- placeholder, см. ниже
 where false;
```

## 9. ЧТО НЕ ДЕЛАЕМ СЕЙЧАС И ПОЧЕМУ

| Не делаем | Почему |
|---|---|
| **Единица измерения `services.unit`** (шт/м²/час/визит) | Владелец её не просил; «шт» зашито литералами в пяти местах — либо все пять разом, либо экран «выбрано м², подпись читает от 3 шт». Отдельная задача, первая в очереди «потом» |
| **Своё поле скидки у услуги** (%/€ + «Действует до») | Четвёртый механизм при трёх с нулём применений на проде; «Действует до» = цена, меняющаяся сама по календарю, без резолвера; в реальном счёте `line.discount` растворяется в цене за единицу (`factor = total/gross`), отдельной строкой не печатается |
| **Тумблер «Участвует в скидках»** | Меняет математику корзины (`applyDiscount` работает по всему subtotal), нет ни колонки, ни читателя, а у оплаченной записи `services/discount_amount` заморожены сервером |
| **Герой ЦЕНА · ВРЕМЯ · ПРИБЫЛЬ** | Жанр страницы-информации на странице-настройке; `cost_per_unit` обнулён в диспетчерской проекции — крупное число уверенно наврёт не-владельцу |
| **Чипы «Проверить на N шт» и строка «Итого в счёте»** | Вторая формула денег документа: реальная строка масштабируется от итога записи (ручной итог у 20 из 30 прод-записей), НДС садится в `issue_invoice`. Число разойдётся с бумагой именно там, где ему поверят |
| **Своя ставка НДС у услуги** | Четвёртый уровень наследования (компания → команда → …), построчного налога в `invoice_lines` нет физически |
| **Перечёркнутая цена в строке списка** | Список пересобран сегодня; переизобретать строку ради скидки, которой нет |
| **Персональная цена «услуга × клиент», сезонная цена с периодом** | Отдельные сущности, не окупаются на прайсе в 3–6 позиций; сезонность уже работает: цена вморожена в снапшот |
| **Минимальный чек, выезд, наценка за срочность, требуемая квалификация** | Выражаются второй СТРОКОЙ прайса или самой командой-владельцем. Правило: если свойство выражается второй строкой прайса — это не свойство |
| **Фото и заметка для бригады (`crew_note`)** | Заводится только вместе с экраном, который её читает |
| **Снос `bulk_threshold/bulk_price`, `material_costs`, `service_price_overrides`, `color`, `category_id`, `available_weekdays`** | Отдельная уборка схемы с миграцией данных, а не побочный эффект нового экрана; `bulk_*` до сих пор читает shared и легаси-веб |
| **Единая функция округления и `totalPrice = lineTotal(line)`** | Предусловие ТОЛЬКО для будущей скидки строки; сегодняшнее расхождение 30,50/31 старше редизайна |
| **Живой каталог переписывает прошлое** (себестоимость меняет прибыль закрытых месяцев; нетронутая строка переоценивается при открытии записи) | Отдельный дефект контура записи, объясняшкой не лечится и в этот заход не входит |
| **Поиск и группировка в прайсе** | Честно на 3–6 позициях; станет ложью на тенанте с 200 — тогда и вернуть |
